# 微信bot v6.25 验收报告

2026-11-02 在本机 Windows、微信 4.1.15.56 的主窗口验收。

## 故障与修复

桌面 v6.24 实际日志显示：主模型已经生成回复，但 UIA 发送失败；本机已升级到微信 4.1.15.56，而恢复方案只覆盖到 4.1.15.50。新增精确对应本机已安装模块的 .56 方案，保留原有三版适配，不按新版本号直接沿用旧地址。

新模块 SHA256 为 e0428a7b691853de496532523c2c09aa095f90941c37c9f4cfb3f137f3c66556。两轮离线分析核对六个完整函数、内部跳转、调用与数据目标映射、Qt 无障碍分类及日志字面串。主开关位于可写且不可执行的数据区，主 gate、getter、setter 指向同一字节；第二候选未纳入。相关证据保留在包外 evidence625 中。

停止机器人后面板仍运行，旧启动器误将面板存活视为机器人已启动。现在复用停止状态的面板时调用正式启动接口，暂停状态调用继续接口，正常运行时不重复启动。不修改账号或环境，也不依靠额外睡眠等待。

未知构建时，发送错误与工作台直接显示实际微信版本和受影响范围，避免只显示笼统的 UIA 不可用。

## 验证记录

六百零五项 Python 回归通过，耗时七十一点九三二秒；三个前端回归套件通过。启动修复经另一代理独立审查，并删除一次重复进程查询；测试覆盖停止复用、暂停恢复、正常运行复用及 HTTP 拒绝。

实机已验证：微信 4.1.15.56 最大化主窗口临时恢复后，搜索框、聊天标题、输入框、消息列表、发图和右 Alt 语音按钮均可读取。两轮临时开关测试结束均成功恢复原值。

文字和图片分别通过原生微信主窗口发送到指定测试联系人。聊天中可见文字回复“收到”和图片气泡。朋友圈实际打开了原生列表并触发刷新。本轮朋友圈验证范围为打开与刷新。

语音使用同一条 2.58 秒的克隆音色样本。通过本机 WeFlow 按会话、方向和时间取回微信实际发送的语音，以连续 30 毫秒达到 −45 dBFS 估算语音起止。录音期间取消重复查询聊天标题后，按钮路径从开始录音到播放样本为 0.125 秒，右 Alt 路径为 0.312 秒。

| 发送方式 | 微信语音总长 | 开头低音量 | 结尾低音量 |
| --- | ---: | ---: | ---: |
| 默认右 Alt | 3.16 秒 | 0.24 秒 | 0.60 秒 |
| 微信发语音按钮 | 3.24 秒 | 0.20 秒 | 0.71 秒 |

源样本前导从 0.56 秒缩至 0.10 秒。自用面板配置的额外录音尾长是 500 毫秒。这两次独立启动发送器，从定位联系人到发送完成分别为 10.03 秒和 10.39 秒，含首次联系人定位、音频播放和设备恢复，未计模型生成时间。早期测试曾遇到控件未显露及临时草稿提示，本次结果对应表中两次实发。

面板停止按钮成功停止本包机器人和 AstrBot，只保留面板端口 8766。重新运行一键启动脚本退出码为零，同一面板进程继续运行，6185 和 11229 恢复监听。状态接口确认机器人运行、WeFlow 和 AstrBot 均已连接。服务器及其他微信构建未参与本轮实机测试。
