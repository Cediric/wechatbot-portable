# 微信bot v6.18 验收报告

日期：2026-10-18。依据用户提供的wechat-bot-log-2026-10-17(1).txt及wechat-bot-log-2026-10-17 (1)(1).txt。这两份是同一轮六点十七运行的不同长度日志，消息编号重合，不能算两次独立复现。

## 上版交付遗漏与回撤

00:15的文字走新增Unicode输入后读回失败；00:16语音已合成，却在联系人查找阶段停止。此前FakeAuto将Unicode事件直接追加到模拟输入框，绕过了Windows到Qt的接收过程，不能用这一模拟结果证明微信输入兼容。库参数顺序正确也不等于真实输入被接受。

本版撤回该输入改道，搜索与聊天正文恢复原来的剪贴板粘贴，移除模拟器“Unicode必然被接收”的假设。没有删除目标、草稿和发送读回核验，也没有在失败时盲目重复发送。

原剪贴板快照要求所有已注册格式均能按内存块完整复制，远控及OLE辅助格式可触发整体拒绝。现在只有存在完整可恢复的Unicode文本、文件列表或DIB图像等标准载荷时，明确的非内容辅助格式才不阻断；未知承载内容格式仍保留。可读的自定义格式继续按原字节保存。快照与最终序号在同一次OpenClipboard锁内取得，避免把延迟渲染本身引起的序号变化当成用户重新复制；写入和还原仍在锁内比较序号，不覆盖用户的新复制。

另外修正聊天和朋友圈共用读回的明确反例：ValuePattern返回空串时，不再提前遮蔽TextPattern中的有效正文。这一反例由代码复现，现有服务器日志没有证明该机器恰好属于此情况，因此不能把它单独说成所有输入失败的原因。

## 录音及朋友圈慢路径

00:18这次语音约71.75秒才失败，其中只有约8.75秒落在已有子阶段计时。录音手势前的_voice_recording_state预查仍枚举整个桌面UIA，该工作不在recording_start_seconds中；上版只修了聊天主窗口发现，遗漏了此入口及朋友圈各自的冷启动入口。同步COM调用阻塞时，外层轮询时限不能把它中断，不能把一秒多的阶段设置视为真实总耗时上限。

本版共用原生顶层窗口枚举，先用原生进程信息筛选，再取得同微信进程的UIA节点并核验可访问窗口类。Qt原生窗口类与自定义UIA类不要求相同。录音预查、聊天首次发现及朋友圈根窗口定位不再遍历无关应用的UIA提供器。已知主窗口仍在当前COM线程重新取得控件，不缓存跨操作COM对象。录音预查单独记录耗时，弥补此前未计时部分。

录音观察保留按钮快速路径，并支持编辑区内嵌套的录音视图，扫描剪去历史、搜索和听写区域；保留右Alt手势、录音确认、播放前准备及失败后的按键释放和设备还原。没有以“合成成功”冒充“微信语音已发送”。

朋友圈保留六点十七的批量滚轮、深度和手动时段处理，本版只补其原生窗口定位慢路径。日志末尾的回顶超时尚不能据合成测试写成服务器已恢复。
