# 微信bot v6.4 验收报告

本轮只修改本地文件及交付包，没有操作服务器或实际微信bot进程。

用户提供的 startup-error(3).txt 表明桥接和 AstrBot 独立环境准备已完成，失败发生在启动服务：6185 和 8766 已有监听，而新解压目录没有能对应这些监听的本包记录。日志本身不能确定占用进程来自哪个目录。

## 修复

- 便携一键启动在任何新服务启动前，检查配置的面板端口与 11229 OneBot 端口；依据实际进程入口、解释器、实例和旧目录记录识别旧微信bot。
- 全部旧候选核验后，先停止桥接并确认 UIA 还原，再正常退出旧 AstrBot。只使用当前源码中的验证及退出代码，旧目录提供记录和实例路径，不执行旧目录脚本。
- AstrBot 登记、就绪和退出统一使用官方入口判断，修复合法管理解释器及官方模块子进程已经通过就绪核验，却被退出路径拒绝的问题；退出后可清理只读旧记录，并发替换的记录保留。
- 已确认退出后最多等五秒让原监听进程释放端口；出现新的占用进程立即停止，不向它发送退出请求。交接失败时不启动半套新服务，错误只显示端口和进程编号，不输出环境变量、命令参数、配置或凭据。

交接不迁移或覆盖旧目录的用户配置、记忆、媒体与 AstrBot 数据。主模型、辅助模型、角色、思考和上下文设置、克隆音色及参考图沿用六点三；版本、插件、诊断和包名同步为六点四。

## 验证范围

独立代码审查通过，针对交接、启动、AstrBot 生命周期、控制台、诊断和进度输出的去重一百六十八项定向回归通过；最终端口等待版本另独立复验全部九十四项交接及启动用例，这九十四项属于上述总数，不重复计数。测试使用模拟进程及隔离测试夹具，没有停止正在使用的应用，也没有调用模型 API。

两份完整包会独立核对全部清单、源码与私有素材字节、压缩包完整性、可写属性、版本和配置保留；对照为精确归档的最终六点三包。SHA 随桌面包文件提供，详细机器审查报告保存在本地工作目录。

本轮没有服务器或纯净 Windows 10 实机重测。无法读取旧进程身份、旧目录记录已丢失，或端口实际属于其他程序时仍须先退出对应程序；不会把这种情况报告为新包启动成功。
