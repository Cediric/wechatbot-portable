# 微信bot v6.33 验收记录

本版针对服务器 11 月 3 日日志中「朋友圈点赞、评论、回复都不工作」与「共享记忆仍未生效」两条反馈。

## 朋友圈主动互动不触发

日志显示 `reply_poll` 正常轮询且 `scanned=20 processed=0`，全程没有一次 `browse` 记录，也没有任何 `manual queued` 或 `manual_browse`。回评轮询扫到 20 条却 0 处理属于正常结果：本期没有针对本人动态的新评论，没有可回复对象。

真正的缺口在调度。主动点赞与评论只在 `now >= _next_browse` 时执行，而 `_next_browse` 仅为进程内变量：

- 15:34:11 启动，`_next_browse` 记为 19:34:11（间隔 240 分钟）。
- 19:29:01 桥接停止，距首次触发还差 5 分钟。
- 该时间不落盘，任何一次重启都按新的启动时刻重新加满 240 分钟。服务在一天内重启三次，主动互动因此始终到不了点。

本地以真实形态的 20 条动态跑 `_candidates(replies_only=False)`，正常产出 2 条点赞、3 条评论候选；`replies_only=True` 产出 0 条。这排除了候选筛选逻辑本身的问题。

本版改动：

- `moments_interactions.py` 新增 `schedule_state` 表保存 `next_browse_at`。启动时读取上次记录：未到期就继续等待，已过期立即到期（时段检查仍然生效），首次使用仍按文档等待一个完整周期。日程写入点覆盖启用切换、周期设置变更和每轮浏览完成。
- 启动日志明确写出下次主动互动的时间与剩余分钟，并说明回评仍按秒级轮询，避免健康待机被误判成故障。
- `skipped` 结果在存在未核验评论时输出 `unverified_comments` 与 `reply_identity` 计数。只记数量，不记昵称、正文或微信 ID。

## 账号核验挡住全部互动

服务器面板显示「最近执行失败 · 朋友圈互动未提交：微信身份卡没有可核验的微信号」。此时调度已经正常（面板出现主动浏览 00:25:57、手动请求已执行），候选也正常，卡在 `execute_interaction` 的 `account` 阶段。

`_read_profile_actor()` 原先要求身份卡内恰好存在一个值控件：`ClassName` 为 `mmui::ProfileTextView`、`AutomationId` 含 `basic_line_view`。真实身份卡的地区、性别与微信号共用同一个控件类，`_unique()` 在多于一个匹配时返回 `None`，于是每次都在核验阶段中止，点赞、评论、回复全部无法提交。

本版改为按位置绑定：先定位「微信号」标签，再取与它垂直居中对齐、位于其右侧的同一行值控件。同一行出现两个并列值时不作猜测，按无法核验处理。控件树不提供矩形时，只有在值控件唯一的情况下才退回原判断。失败时把卡片结构写入日志，仅记录控件类型、类名、AutomationId 末段与名称长度，不记录昵称、微信号或号码。

新增两项回归：多行卡片绑定到正确行；缺少「微信号」行时停止而不猜名字。

## 回复按「人」判定

真机日志出现两次回评失败：

- `action=reply stage=source … 同一动态存在同名同正文评论，无法唯一对应真实评论 ID`
- `action=reply stage=reply_target … 回复对象没有在编辑器中确认`

服务器截图显示，点击评论后编辑器里只有一行灰字占位「回复 张修齐」，它是输入框自己的占位提示，UIA 读不到；而同一条动态下五条评论全部来自张修齐本人。

据此确定两条规则：朋友圈回复的对象是人，同一人在同一条动态下的多条评论回复任意一条效果相同；收件人提示读不到不等于点错了人。

改动：

- `_fresh_source` 的冲突检查改为按作者区分。同名同正文若属同一作者，视为可互换并继续；跨不同作者仍抛 `comment_identity_ambiguous`。
- `_choose_reply` 命中多个同名控件时，只有在原生数据证明这些内容都属于同一作者才取第一个，否则仍按无法唯一对应停止。控件没有 RuntimeId 时照旧停止，因为它无法被驱动。
- `_verify_reply_caption_ocr` 改为三态：`True` 指向本人，`False` 指向别人，`None` 完全读不到。只有 `None` 会进入兜底。
- 兜底路径 `_reply_target_by_native_identity` 重读原生评论列表并比对，确认未变、未被回复、作者唯一后才继续，并写入 30 秒内的复用证明，避免重复截图。

`False` 仍然意味着「读到了一个明确指向别人的提示」，这种情况绝不会因为兜底而放行——测试里「回复 Bob」「回复 Car」「回复 Carol2」等七种可读但错误的文本继续拒写。

## 共享记忆跨会话未生效

`memory_scope=shared` 已开启，`search()` 的跨会话分支要求同时满足：作用域为 shared、`actor_id` 在本次发言人集合内、来源不是 legacy、且 `audience == 'profile'`。

`_audience()` 在没有明确标签时默认返回 `session`。抽取提示词的 JSON 契约原本只有 `content`、`evidence`、`fact_key` 三个字段，`audience` 仅出现在后面的说明文字里。模型按示例输出时不会带上该字段，于是「我喜欢喝咖啡」还能靠旧正则兜底判为 profile，而「我叫小明」「我是山东大学学生」一类稳定事实一律落到 session，跨会话永远取不到。

本版把 `audience` 写进 JSON 契约并标为必填，同时说明写 profile 的后果（会在该微信用户的其它会话被召回）与边界（保密、他人、私下约定、关系、联系方式、身体、财务、位置一律 session）。

本地以临时库验证：私聊写入 `喜欢喝咖啡`（profile）后，在群聊会话中检索可以召回；同一条在 `scope=session` 下不召回；标为 session 的记忆不会跨会话出现。

## 关于「刚才私聊说了什么」

该测试问的是短期对话，不是长期事实。抽取只保留带逐字证据的稳定偏好、约定或关系，单句「oi」不会入库，因此换会话后没有可召回内容。这是既有设计，本版在 README 中写明，不把「短期对话也可跨会话复述」当作已实现能力。

## 测试

- `tests/test_moments_interactions.py` 87 项通过；新增 3 项：重启后保留未到期日程、过期日程重启即到期、首次仍等待完整周期。
- `tests/test_moments_social_sender.py` 174 项通过；新增 2 项身份卡测试，另按「回复只看人」更新 5 项旧期望（同一人重复评论、空白归一化冲突、引用不同但同一作者、重复渲染叶子、读不到收件人提示）。
- 全部朋友圈相关测试（`test_moments_*.py`）396 项通过。
- 全量 1789 项：9 失败、240 错误、6 跳过，与改动前基线完全一致，无新增失败。失败项为既有问题（脱敏正则把「退出码 17」写成「[已脱敏]7」等），错误项为本机缺 `requests`、`PIL`、`psutil` 等运行依赖。
- 记忆侧新增验证为临时脚本，未并入正式测试集。
