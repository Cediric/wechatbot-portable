# 微信bot v6.6 验收报告

本轮根据用户提供的 startup-error(4).txt 修复本地启动交接并重新交付完整双包，没有操作服务器或实际微信服务。

## 证据与修复范围

日志显示环境导入检查已完成，失败发生在旧版本交接：8766 的监听进程已经能够对应旧桥接入口，但随后旧进程记录检查失败。旧版同一句错误涵盖记录缺失、损坏、陈旧及命令核验异常，不能仅凭此文件判定目标机真的没有 bridge.pid，也不能判定一定是虚拟环境解释器差异。

本次将旧桥接进程记录从交接的必要条件改为可清理的记录。直接核对当前监听 PID、原生创建时间、实际解释器、绝对 main.py 入口和对应面板端口，获得只保存在内存中的本次身份，不重写旧包文件。

所有候选确认后仍先停止旧桥接、再正常退出旧 AstrBot。桥接停止复用原面板凭证和 /stop 接口；确认桥接已停止且 UIA 临时状态还原后，才精确结束已经核验的进程。端口换人、进程创建身份改变、错误入口、陌生进程或还原未确认时不继续操作。

旧记录缺失、损坏或不对应实际进程时保持原状；只有原记录确实属于已退出的进程且字节未被替换时才清理。原有单包 stop_owned_process 的行为保持不变。

## 验证

完整启动控制八十八项、跨版本交接二十三项、实际当前 helper 集成十一项，共一百二十二个不同用例通过；集成测试使用临时旧目录，实际加载当前验证代码，覆盖记录缺失、损坏、陈旧、并发替换，以及入口或监听身份变化和还原失败。停止动作在离线测试中模拟，原有原生虚拟环境测试仅启动无害子进程并自然退出。

修改由两位子代理独立交叉检查；完整双包另行独立核对 CRC、文件清单、源码字节、版本、私人配置隔离和 SHA-256。最终测试日志及审计报告留存于构建目录。

主流程、模型 API 与选择、思考强度、上下文、角色卡、音色和参考图与已验收的六点五保持一致。此轮不宣称目标服务器已实机启动成功；已有数据留在旧目录。
