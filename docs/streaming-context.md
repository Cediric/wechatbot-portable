# 流式回复与上下文设置

“模型工作室”分别保存五种用途的 API、模型、提示词、思考控制、上下文上限与输出预留。主模型负责全部对外创作及媒体理解；决策模型只做决策。视频以采样画面输入，不另设聊天识图模型；旧生图提示词子模型字段只保留兼容，不再调用。

主模型的角色卡也会进入实际聊天请求。角色主人的显示名只是文学设定；请在“角色主人对应的微信 ID”中填写核验后的微信 username，才建立该身份对应的关系。群成员仍按自己的微信 ID 分别识别，不能继承另一个人的关系和记忆。

打开“边生成边回复”后，AstrBot 向主 API 发起真实流式请求。微信按完整短句收到逐步生成的回答；链接与代码保持完整，推理过程不作为聊天正文。首次发送补足最短响应时间，后续片段按同次回复的气泡间隔执行。

纯语音时收集主模型的完整台词交给语音接口，不先发送同句文字；旧版文字加语音选项按纯语音处理。文字已经流式发出时，不再将同一段补成语音。朋友圈发布、评论回评和生图提示词各自发起独立的主模型写作任务，输出只进入对应出口，不能将JSON、决策理由或画面提示当作聊天文字。

主模型上下文上限最多 500,000 token。此数值包括角色卡、系统提示、历史、当前输入、媒体、工具和输出预留。启用“自动摘要旧对话”后，接近输入预算的触发占比时，将更早的完整对话合并成同一会话的摘要，保留近期原文与未完事项。摘要调用仅在需要压缩时发生；失败时裁剪完整旧轮次，不无限重试。

摘要与长期记忆用途不同：摘要维持本次会话的连续性，长期记忆保存有原文证据的事实与偏好。默认按会话与真实发言人隔离；手工公共记忆才用于多会话。两种便携交付包都不复制已有聊天、摘要数据库或记忆数据库。

记忆抽取每次只读本次待处理的原始证据及其身份信息，不累积主聊天的整段历史。原文长度默认最多 8,000 字符，可在面板调至最多 32,000；上下文上限仍包含提示词、消息封装和输出预留。接近预算时，在本机挑选完整原文片段，优先保留明确偏好、约定与后来的纠正，保留字符范围；这个步骤不调用额外摘要模型。抽取证据必须逐字落在某一个保留片段内，禁止把不同片段拼成证据。长度截断后未结束的尾句不能成为长期事实证据，避免遗漏后半句的否定或修正。设置很大的记忆上下文上限不会突破原文字符上限，也不会自动扩大每次待抽取消息。

开启记忆时，群聊在参与判断前保存真实发言人的原始证据，即便这一轮决定不回复也保留。“记住不要放香菜”“记住以后叫我小陈”等明确请求按原话即时保存，不同步调用记忆模型，也不把原话提升为系统规则。抽取任务持久化，重启后继续；旧证据的重试不会覆盖较新的同类事实。

开启「同一微信用户跨会话」时，聊天请求按核验过的微信 ID 取回普通兴趣、口味或称呼。先选与当前消息相关的事实，最多用两条仍清晰的人物事实补足上下文。自动抽取的事实超过三个半衰期后只参与关键词匹配。新证据可更新同一偏好，单纯检索不会刷新证据时间。发言者要求保密、涉及隐私或不确定能否分享的事实只在原会话使用。旧记录没有共享标记，只有能从旧原文明确识别的普通喜好或称呼可跨会话。

`/reset` 和 `/new` 会先把本会话尚未抽取的完整记录按成员分批写入持久化队列，再交给 AstrBot 清空或新建上下文。同批命令前后的聊天分开处理，不等记忆模型返回。已保存的长期事实保留，本会话短期媒体关联和发送反馈同时清空。

主模型和辅助决策会取得本会话近期实际发送反馈，区别文字、语音、图片、表情的已确认、未确认、未完成和取消。只有发送器确认过的内容才能称为已发送；历史里的生成稿不能作为发送凭证。分段只成功一部分时，历史和反馈只记录实际成功部分，语音反馈不意味着相同文字也发过。这份反馈最多保留两小时，进程重启后清空。

同一人在同一真实会话先发图片、视频或表情再追问时，可带入三分钟内的原始媒体供主模型理解；没有明确指代的短句只在四十五秒内关联一次，不相关文字会结束隐含关联。不同会话与群成员之间不串用媒体，不新增识图模型或图片下载请求。

思考设置须符合供应商接口。DeepSeek 使用关闭、low、high、max，不能指定精确思考 token 数；千问接口可使用其支持的 thinking_budget。最大输出也须留足思考与最终答案的空间，思考越多通常越慢。上下文计数是保守估算，图片、视频采样画面和工具结构开销会预留额外空间，不能当作供应商精确 tokenizer 统计。

API 地址、密钥、模型、角色卡和预算保存后用于后续请求；正在处理的请求保留自己的配置快照。先保存再测试，确认 API 支持所选参数。自动朋友圈发布与互动有各自开关、轮询时间、日限额和真实 ID 校验。

“拟真与朋友圈决策模型”共用一套独立模型设置，按真实微信 ID 获取当前人物的相关聊天、朋友圈互动和角色关系。面板可调整是否启用私聊拟真决策，以及各次带入的聊天和互动条数；开启私聊判断会增加一次决策请求。朋友圈仍逐条隔离：该条查看、决策、主模型按需撰写和执行核验完成后，再处理下一条。跳过、点赞不额外调用写作。

共享角色卡来自桥接的 `bot_persona`，主聊天、群聊判断、拟真/朋友圈决策、发布决策和生图提示词均注入同一张卡及主人真实身份规则。各模型另有自己的任务提示词；修改主模型专用提示词不会同步给辅助模型。记忆抽取与摘要只处理证据，不扮演角色。面板保存共享角色卡后，下次请求生效；仅在 AstrBot 的独立角色编辑器里修改不会同步回共享角色卡。

聊天长度在主模型自定义提示词中设定，默认通常单条不超过十五字。非流式回复按完整句和换行分泡，超过气泡数量上限时合并完整尾部，不丢内容。流式同样只在完整句和换行处出泡，不按字符阈值强拆长句；仍保留最大缓冲保护。没有句末标点时等本段生成完再发。

回复耗时日志使用 `[耗时]`（桥接）及 `[latency]`（AstrBot）标记。同一轮用请求编号的十二位摘要 `turn` 关联，不记录聊天正文、真实微信 ID 或密钥。桥接日志区分消息缓冲、决策、本地准备与微信发送；AstrBot 日志区分主模型上下文准备、首段正文和首个完整句就绪。各段的 `seconds` 有自己的起点，不能把累计时长直接相加。首条发送完成只表示微信本机界面已接受，并不证明对方已收到。

工作台“回复耗时与运行状态”汇总本次进程各阶段最近二百个样本的最近值、平均值、百分之九十五分位及样本数。首条文字和语音的端到端时间从真实收到消息计至本机微信界面确认，包含缓冲、模型、排队和发送；微信发送一行仅记录发送器成功确认的调用，不当作端到端延迟。第一条已确认、后续失败时，首条样本仍表示已发生的首条确认，不表示整轮全部成功。没有真实接收基线的直接发送不补造端到端样本。发送任务排队包含已经开始的失败或取消任务，语音排队仅来自确认语音的记录；页面刷新不重复采样。

语音准备耗时包含缓存命中，实际合成一行只统计未命中的成功合成，两者分开显示；缓存命中、未命中与合并等待次数另列。采样仅保留耗时与时间戳，不存正文、收件人、密钥或音频路径；进程重启后重新累积。队列当前任务、已用时间及卡住或恢复状态来自现有运行快照，打开面板不触发 UIA 扫描、发送或模型请求。

`main_first_content` 和 `main_first_sentence_ready` 从本轮首次主模型请求钩子开始计算，包含上下文整理、SDK 准备和模型等待，并非纯 API 首 token 耗时。完整句就绪是正文规则校验和微信发送之前的候选，不等同发送成功。只为真实流式的非空文字记录这两项；失败、取消、纯媒体或非流式回复不虚构相应指标。

私聊拟真决策开启时，没有明确语音或图片要求的聊天先完成拟真判断再调用主模型，两次思考和网络等待会叠加。已经明确要求且功能已启用的私聊语音或图片，直接进入对应流程，不再调用随后会被覆盖的拟真决策；图片写作仍带相关聊天与朋友圈上下文。群聊仍保留参与判断。上下文上限是允许的最大输入，并不表示每次都带满。最低响应时间从收到消息时计算，只补尚未经过的时间；消息合并和气泡间隔也不应当与模型耗时混为一谈。

明确的图片请求在生成、发送完成后，不自动附加一条语音占用发送队列；同时明确索要图片和语音时仍可发送两者。“然后发个图片”“顺便发张图”等追加表达也会识别。合并消息要求先语音后图片时，图片可先生成，但只放入本轮内部计划，等语音被微信界面确认后再发；主模型此时只看到图片已准备、尚未发送。语音不确定时不继续发后图；语音已确认而图片失败时保留部分成功结果，不重发语音。

普通后续消息继续留在同一真实会话的缓冲区，等待前一轮流和语音回执结束后再处理，不因为新输入就取消已在合成或排队的回复。明确“取消”“别发了”等停止要求会立即作废旧轮次，并通过 AstrBot 停止旧推理；暂停、停止和设置代次变化仍可中断。失败、取消会释放等待；未闭合流若达到现有模型超时加发送等待上限仍无进展，会结束旧轮次，不把去重记录的保留期当作等待期。已开始的发送及语音后续图片任务仍要等其真实队列回执结束，避免前后操作重叠。自然表达“你发个语音我听听”会作为明确语音请求，引用、转述和否定要求不会获得这个标记。

`bridge_prepare` 中的 `tool_seconds` 包含图片获取和微信发送，不能当作纯生图 API 时间。新增 `image_generation` / `image_search` 与 `image_dispatch` 分开记录这两部分；语音也分开记录合成、排队和界面发送。日志中的“已加入 AstrBot 待转交队列”只代表已本地持久化，成功握手和实际 WebSocket 转交另行记录。

各语言模型另外读取代码内置的协作约定：主模型创作，拟真、群聊和朋友圈模型决策，记忆模型处理事实，生图与语音接口执行合成。内置约定不在面板作为可覆盖提示保存；专用提示替换也不能删除它。主模型同时收到程序提供的本轮输出计划及实际图片执行状态，避免重复宣布决策、混淆角色或在失败后说“已发”。摘要有自己的固定事实整理职责，画面和语音接口只接对应提示词或台词，不把内部协作说明画进图片或读成语音。

“优先使用右 Alt 录音”默认开启。按住右 Alt 录音，松开发送；关闭后改用微信的发语音按钮。一次语音只使用一种方式。听写转文字和语音消息是两个独立入口。图片请求可以自然表达为“发张照片看看”；生成或发送失败会如实反馈，不能按一条文字承诺判定图片已发。

语音内容缓存只复用已完成、可读取的有效音频。最终台词、服务渠道与地址、模型、音色、语速、音调、音量、输出格式，以及 API 凭据和机器人账号指纹共同决定缓存身份；其中任何一项改变都不会复用旧音频。命中不会修改台词或音色，同一桥接进程中的同键并发请求只合成一次，失败不自动重试。等待期间取消的回复仍不会拿音频去发送。

缓存沿用现有保留天数（至少七天），成功复用会刷新最后使用时间；过期或损坏的文件不命中。缓存文件仍使用原试听接口支持的受管文件名。面板统计只读取内存计数与最近两百次成功未命中合成的耗时，不扫描目录，不包含正文、密钥或文件路径。缓存命中只表示音频可复用，不能代表微信已经发送成功。

共享合成的等待者被取消时会及时离开等待，正在合成的唯一请求仍可完成并缓存，供其他未取消的调用复用。缓存目录与保留期未变时，目录清理每十分钟最多执行一次，命中时的单文件有效性检查照常。语音已经确认发送后，记忆写入失败单独记录，不再阻断同轮已准备图片，也不把语音改报为发送失败。

群消息缓冲和媒体加载保留收到的原生艾特标记，并传入群聊决策上下文。判断服务不可用或结果解析失败时，直接叫到机器人的消息仍可回退文字回复；正常决策选择不回复仍生效，不根据昵称替换真实发送者或群编号。
