# 微信bot v6.23 验收报告

日期：2026-11-01。本版清理回复链路中可证明重复的决策、预算扫描、媒体校验和 UIA 属性读取，减少不必要的等待。人设、模型、音色、朋友圈计划、最短响应时间与气泡节奏沿用当前自用设置。

## 减少的工作

| 场景 | 六点二十二 | 六点二十三 |
| --- | --- | --- |
| 私聊明确请求已启用的语音或图片 | 先调用拟真决策，再覆盖回复或输出类型 | 跳过这轮决策，直接进入指定流程 |
| 空队列等新消息转交 AstrBot | 每八十毫秒查询一次 | 本地持久化提交后直接唤醒 |
| 当前会话有效历史已满额度 | 继续查询相关群记录，最后全部截掉 | 满额即停，最终上下文相同 |
| SDK 提供最终 HTTP 入口 | 转换阶段和最终入口重复扫描预算 | 只在最终入口检查一次，仍包含后加工具 |
| 一千轮合成历史裁至最后一轮 | 消息计数调用一百万一千次 | 消息计数调用两千次 |
| 同次 HTTP 图片处理 | 四次打开图片，重复完整解码 | 两次打开，复用本次完整校验 |
| 同次 Base64 图片处理 | 三次打开图片 | 两次打开，一次完成完整校验 |
| 普通单文本流式片段 | 重复校验两遍字符 | 复用本次流式校验结果 |
| 合成 UIA 单句发送路径 | 三百四十三次属性读取 | 三百零五次属性读取 |

主模型上下文裁剪基准对比同一个六点二十二正式包、同一千轮合成历史和相同输出；五次运行中位耗时由 426.23 毫秒降至 3.87 毫秒。历史仍按完整轮次处理，原始历史只复制一次；没有新增跨请求历史缓存。基准记录于包外 `model-latency623-benchmark.json`。上述数字是本地裁剪或测试替身的调用数量，不能解读为实际微信端到端回复提速比例。

Outbox 的空读取与清除通知在锁内完成，消息提交后再唤醒，避免丢唤醒；等待线程只取出内容供调用方查看，不消费、不发送。暂停、会话代次和发送确认保持原有边界，收到事件后仍先确认当前运行状态再转交。

私聊显式媒体请求使用现有意图识别，不新增关键字匹配规则；否定、引用及关闭功能时仍走原流程。图片提示仍由主模型结合相关聊天和朋友圈资料创作，语音台词仍由主模型生成。群聊是否参与仍由群聊决策决定，普通私聊仍按当前拟真设置判断。

最终 HTTP 预算入口不可用时保留 SDK 转换阶段检查。媒体校验复用仅限同次内部处理；调用方提供的本地文件仍完整校验，外部消息不能标记自己为已检查。窗口身份合并读取放在原生归属查询之后，标题在下一轮重新读取；同名搜索结果稳定等待、草稿保护和实际发送确认没有删除。

## 验证

最终合并回归共七百二十五项全部通过，耗时六十秒，覆盖消息桥接与真实本地 WebSocket、入队唤醒、身份隔离、媒体分流、完整历史裁剪、插件加载、便携配置及模拟 UIA 发送。此时间为测试总耗时，不是微信回复时间；日志位于包外 `final-v6.23-regression.log`。

三个子代理分别处理 UIA、模型上下文和输出分发，主代理处理直接媒体请求与入队唤醒。交叉审查核对了模型校验入口、媒体内部所有权、文本规范化、队列唤醒、暂停及原生会话隔离。完整双包另行核对文件清单、版本、公共源码和自用覆盖层，结果记录于包外 `final-v6.23-independent-zip-audit.json`。

本轮未调用付费模型或操作真实微信，也未在服务器测量收消息到首条回复的时间。因此不能保证每次回复缩短固定秒数；主模型、语音和生图服务的网络与生成耗时仍需实际运行日志衡量。现有最短回复时间继续从收到消息起计算，模型处理已经经过的时间不会重复等待。
