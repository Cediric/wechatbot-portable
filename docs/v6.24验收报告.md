# 微信bot v6.24 验收报告

日期：2026-11-01。用户选择“停止机器人和 AstrBot，保留面板方便重启”，本版按此语义修正服务控制。

## 行为变化

原“停止”仅取消收发任务，AstrBot 与后台记忆抽取继续存在。现在面板的停止操作先取消微信收发、朋友圈发布与互动，暂停记忆模型抽取，再退出本包登记的 AstrBot。面板 HTTP 服务、其进程管理器和面板内待机线程继续存在，因此仍看到它们的 Python 进程是正常的；不会按 `python.exe` 名称清理电脑上的其他程序。

再次点击“启动机器人”使用现有启动器恢复本包 AstrBot，然后开启桥接及记忆抽取。该操作不重装环境、不重新初始化账号或密码、不打开重复浏览器。AstrBot 连接状态单独显示，启动请求已受理不等于模型服务已经完成冷启动。源码模式连接的外部 AstrBot 不受本包进程控制，面板会明确提示。

记忆暂停仅影响模型抽取，不修改用户的记忆开关，不关闭数据库，也不隐藏已有记录。未处理任务继续保存在本地数据库，旧请求的取消标记和代次阻止其迟到结果回写。停止期间保存设置不会启动新的抽取任务，重新启动后继续处理待办。

AstrBot 正常退出先发控制台退出信号，面板路径给八秒宽限；随后只对创建时间、程序入口、命令和实例目录再次匹配的本包残留进程执行结束，并确认退出。启动器先退出、子进程仍在时不再提前报告成功；成员快照保留在原进程记录中，可供重试使用。下一次启动会先处理明确记录的未完成退出。未知身份、权限失败或进程仍存活时显示未完成，保留重试入口，不报告假成功。

面板启停使用独立服务操作入口；配置重连、内部恢复仍使用桥接内部入口，避免修改普通设置时误停 AstrBot。朋友圈调度线程在面板中待机，停止时取消令牌与运行状态共同阻止模型和桌面动作；不销毁这些线程，避免旧请求尚未返回时快速停止、启动造成调度无法恢复。

## 验证

四百九十一项 Python 回归通过，耗时三十三点六三秒，覆盖面板启停、AstrBot 子进程退出和重试、停止后修改设置、记忆暂停与恢复、朋友圈调度、便携启动与进程管理。前端服务控制九项场景及原有待处理消息、朋友圈面板回归通过。

多代理分别检查面板操作、后台记忆、AstrBot 进程归属，并交叉复核启停顺序及快速重启。回归使用模拟模型、进程和桌面接口；不对实际微信发送消息，不终止电脑上正在使用的真实服务，也未在服务器实机验收。

双包独立审计核对版本、公共源码及变更范围，核对一百八十七项自用配置、银月角色卡及八项参考素材保持。运行进程记录、会话和记忆数据库不进入交付包。包外审计结果为 `final-v6.24-independent-zip-audit.json`。
