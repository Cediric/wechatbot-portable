# v5.3 记忆审查与使用

SQLite持久化、本地中文bigram关键词检索、独立模型抽取、有预算注入。没有增加向量库；本地检索无需额外模型等待，但同义改写可能漏检。

## 修复与归属

- 记忆带真实会话ID、实际发言者微信ID、原消息ID、逐字原文证据、来源、事实字段和更新时间；改备注不改归属。
- 默认session只检索当前会话、相关发言者和人工公共记录；A的偏好不当成B的。无成员ID的旧群记录保留供查看，不注入。
- shared 按真实微信 ID 跨会话召回同一人的日常喜好和称呼。没有关键词重合时最多补两条近期人物事实；抽取的事实经过三个半衰期后不再主动带出。私密事实只供原会话检索。朋友圈shared模式可看近期聊天，属于明确开放的共享范围。
- evidence须逐字存在于原消息，content须为证据连续片段；转述是用户陈述，未外部核实。拒绝明显任务指令，JSON资料边界提醒模型不执行记忆指令。
- 同会话/同人/同稳定fact_key更新最新明确陈述；内容去重，人工/旧版来源有区别。模型分类仍可能出错。
- 助手已确认回复写chat_log(role=assistant)，不抽为用户事实。失败未确认尾部不标成已回复。
- 注入按完整JSON字符计预算，默认2400字符，包括转义和资料提示；不会截成破损JSON。
- 单抽取worker、有界队列及去重；关闭/清空使旧抽取结果失效。关闭快速取消，后台请求在超时范围内收尾，不能重新开库或晚写。
- SQLite加字段迁移保留数据，旧私聊actor补为原session，旧群不猜发言者。

## 面板

模型工作室→共享记忆：模型、提示词、思考/上下文、检索条数、注入预算、单条/抽取上限。全部设置→记忆与维护：范围与数据库。记忆页：搜索、查看归属/证据及原消息ID、逐条删除或清空。清空全部同时删除本地聊天日志，并使尚未完成的抽取失效；确认弹窗会说明这一点。改库路径完整重启，升级备份整个data目录。

## 边界

测试覆盖归属、迁移、证据拒绝、更新、预算、去重、取消及清空竞态，真实长期聊天/付费抽取尚未实测。同义词、否定、矛盾陈述和字段分类可能影响检索；资料边界降低提示注入风险，不保证模型永不误解。
