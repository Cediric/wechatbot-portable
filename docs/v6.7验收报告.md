# 微信bot v6.7 验收报告

根据十月十四日运行日志和朋友圈截图修复本地文件，交付干净包和自用包两个完整便携包。本轮没有控制服务器、调用付费模型或实际发送微信消息。

## 已确认的原因与修复

语音成功记录中，按下录音至确认录音状态耗时2.265秒，之后还有目标核验和播放准备。该路径能产生明显的录音前段空白；仅凭日志不能排除合成音频本身的静音。现将播放通道准备放在录音手势前，录音控件检查跳过已知历史、搜索和听写子树，保留实际录音窗口及文档型录音控件支持。播放前仍核验当前前台、录音状态和真实目标；取消时释放按键、鼠标并还原音频设备。新增 gesture_to_play_seconds、post_observation_guard_seconds 和 voice_player_prepare_seconds，便于下一次区分录音等待和音频静音；不截掉原音频内容。

截图明确显示“请配置当前账号的真实微信 ID”，同时错误显示“浏览中”。这是机器人自身账号编号缺失，不是用户没开启模块。现在在排队前检查，面板显示“待配置账号”并提供入口；固定的拒绝原因不会被写成成功。后台记录排队、开始和最终结果，成功、失败或阻塞后均结束运行状态。

一键启动可从本机 WeFlow 配置的 myWxid 填补空 bot_wxid。前提是接口能力核验成功，配置启用、本机绝对路径、回环地址、端口与非空密钥相互一致，且编号格式有效；手填值保留。不读取昵称、角色主人或数据库目录推测编号，服务用户名、群 ID 和公众账号不作自身账号。来源是 WeFlow 保存的所选账号，并非当前微信运行状态的独立证明；用户仍需确认微信和 WeFlow 使用同一账号。

发布调度采用明确的下次检查时间，启用与周期热更新会唤醒调度；私聊优先或条件暂不具备时保留到期任务，条件恢复后继续。互动中仅完成有效浏览才消耗主动浏览周期；暂时读取失败按10至60秒退避。首次启用建立旧评论基线，不自动补回历史评论。成功核对未确定发布后重新等待完整发布周期；核对失败继续暂停。

150分钟发布决策、240分钟主动点赞评论、5秒新评论检查、私聊结束并空闲60秒的默认设置保留。手动浏览可提前触发，但执行受活跃时段、私聊优先、身份和待核对状态约束。面板显示最近检查、阻塞原因、手动任务结果和下次发布检查，正常等待不会被渲染成异常。

## 验证范围

- UIA发送173项、语音绑定34项及版本无关UIA两项回归通过；其中8项录音关键边界另经独立代理重跑。合成桌面用例覆盖录音文档控件、300条历史子节点不扫描、播放准备在录音前、取消与设备还原。
- 最终朋友圈、调度和生命周期171项回归通过；覆盖首次等待、热更新、私聊让出、失败重试、旧评论基线、待核对状态和账号缺失不启动后台线程。
- WeFlow账号同步9项与面板路由35项，共44项通过；覆盖三条成功路径、探测失败、手填值、空或相对 APPDATA、端口/密钥不匹配和服务账号拒绝。
- 两个前端行为测试通过，覆盖截图状态、固定错误、手动结果保持、正常周期等待及待核对界面。
- 语音、朋友圈调度、账号来源分别由子代理交叉复核；完整双包另行独立核对CRC、文件清单、源码字节、版本、私人配置隔离和SHA-256，审计结果保存在构建目录。

这些是本地回归与合成桌面验证，不宣称目标服务器的语音前段已经实测消除，也不宣称朋友圈在目标机器已实际发布。合成音频原文件未提供，无法测量其中静音长度。新日志能够定位下一次运行的录音等待；朋友圈需先具备正确自身账号、模型、WeFlow接口与可用UIA。

## 配置与便携性

自用配置逐项与已验收六点六比对；模型渠道和选择、思考强度、上下文预算、流式、压缩、银月角色、克隆音色与三张参考图保留。干净包没有私有配置、密钥、角色或参考图。两个包共用相同公共源码和依赖，包含包内Python、桥接与AstrBot独立环境的安装资料以及原有启动交接修复。

解压完整包并双击一键启动。现有配置和记忆仍在旧目录，新目录不会自动覆盖或合并；迁移说明见[便携运行说明](../portable/README.md)。本轮未重新执行纯净Windows10虚拟机安装或目标服务器实机测试。
