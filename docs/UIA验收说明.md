# 微信bot：UIA 验收说明

当前版本的兼容资料：以下实机记录对应历史测试构建。v6.1 的正常UIA与多构建恢复资料、四点一十五点五零离线核验及运行边界见[微信UIA兼容性](微信UIA兼容性.md)；新增构建不能沿用旧记录声称实发通过。

## 当前结论

本机微信 **4.1.13.65 的主窗口已实测恢复 UIA 控件**，并验证搜索、编辑器值读回和 UIA 按钮发送文字。项目纯文字与带图朋友圈、刷新、点赞、评论及定向回复均已实机验证；发布和回复另经独立截图核对，临时状态已还原。定向回复的可视提示以本机 OCR 补充，定位、输入与发送仍由 UIA 执行。最终模拟回归与多智能体交叉审查结果见 [交付验收报告](交付验收报告.md)。

v5.3末轮在最大化主窗连续完成本次测试动态的两条定向回复：上一条操作将封面滚出可视区后，再次账号核验在同一主窗内回顶并检查原生ID。独立原生记录审查确认每轮只新增一条，原评论和作者准确对应，无错发、重发或结果不确定；临时UIA状态与WeFlow原API设置已还原。托盘、Codex通知遮挡及修正前误开作者资料卡的尝试均在提交前被拦截，零提交。最终包内Python3.12.12全量833项通过、无跳过；本轮范围及证据见 [v5.3验收报告](v5.3验收报告.md)。

**完整 WeFlow → AstrBot → 收到消息后回复链、聊天图片/表情、语音设备录制及付费模型仍未完成实机验收。** 这些与已经完成的项目朋友圈发布分别记录。实测仅适用于本次核验的模块、版本及账号，不能推断所有微信 4.x 的情况。

用户已明确授权单字节临时恢复及两种实际发表。测试图通过完整 PNG 解码后由项目 UIA 自动选入，成功发表；纯文字也由同一公开方法独立通过。具体测试标识、确认方式与还原结果见 [朋友圈实测记录](朋友圈实测记录.md)。正式自主配图已接入项目 API；当前未配置生图和决策模型密钥，真实付费 API 链尚未执行。

UIA 读取的是应用提供的无障碍控件树。截图能看到聊天界面，并不保证应用会提供对应的搜索框、聊天标题或编辑器控件。只有外层窗口时，改控件名称、延长等待或直接按回车不能补出内部控件。

## 本机检查结果

常规 Sky 检查了主窗口、搜索框及“文件传输助手”搜索结果、输入区域、自用账号的独立聊天窗口和设置窗口，最初均只返回 `Window → Weixin Pane → MMUIRenderSubWindowHW`。通用设置未发现无障碍开关，焦点或控件名称调整本身未解决空树。

正式发送要求在微信主窗口内完成。独立聊天窗口只用于排除无障碍提供者与焦点问题；项目不会选它作为发送目标，也不会双击会话将对话弹出。

经用户授权，先对自用账号“自用测试联系人”进行窗口输入测试并收到“收到”；该次使用鼠标键盘，不能算 UIA 验收。随后在已核验进程和 DLL 身份下，将一个已复核数据字节临时从 `0` 改为 `1`，不重启、不弹出对话。主窗口一次 Tab 刷新后出现搜索、`session_list`、`current_chat_name_label`、`chat_input_field` 和 `chat_message_list` 等控件。

Sky 在主窗口通过 UIA 设置搜索内容，观察到唯一实际 `search_item_自用测试联系人`，点击后聊天标题和编辑器仍对应目标；另一次测试通过 UIA 写入草稿、准确读回 Value、点击发送，并在主窗口观察到新气泡与清空的编辑器。还原字节为 `0` 后，控件树恢复为外壳。这证明本次控件暴露依赖该状态。**这些是外部 Sky 的机制和控件验证，不等于本项目 UiaSender、消息身份映射和协议全链路已实测通过。**本轮未实现或使用 OCR。

朋友圈同样位于主窗口中：一次 Tab 刷新发现页后，UIA 可以读取并点击“朋友圈”，出现 `sns_list` 与 `sns_window_tool_bar`。再次点击已选中的“朋友圈”会关闭该页，因此项目先检查列表，已经打开时不重复点击。工具栏“发表”右击后出现 `XMenuItem` 的“发表文字”，点击后是主窗口子 `Window`：`SnsPublishPanel`，内含唯一无名称 `Edit`、发表和取消按钮。左击工具栏“发表”打开标准文件对话框；文件名 ComboBox 和内部 Edit 的 ID 均为 `1148`，打开按钮为 `1`、取消为 `2`。文件项改名控件 `System.ItemNameDisplay` 不能当文件名输入框。

实际项目测试采用同一主窗口；文件路径写入后读回，附图网格中核验唯一真实图片项。正文通过唯一编辑器的 UIA ValuePattern 定向设置并准确读回，再核对发表按钮与预览身份。已分别观察到纯文字动态和含一张猫咪图片的动态，编辑窗口关闭。Qt 小菜单不能主动激活，文字入口专用点击保留主窗口前台并重新核验原主窗口、菜单和菜单项的真实 RuntimeId。重启后的实机测试重新核验进程创建身份，没有沿用旧 PID/句柄证据。

## 已实现的保护

- 严格按微信进程、主窗口类与 Qt 外壳完整标题识别主窗口，排除独立聊天和设置窗口；微信稍后启动或重启后重新发现，不依赖旧句柄。
- 每次发送重新搜索，要求精确且唯一的目标、聊天标题和编辑器焦点确认；同名目标无法充分区分时取消发送。旧备注与缓存名字不能直接绕过确认。
- 支持 WeChat 3.x 的 `WeChatMainWndForPC`，以及已经暴露 `mmui` 控件的 Weixin 4.x；兼容新版点分隔 AutomationId 与 Value/Text/Legacy 无障碍值读取。
- 聊天与朋友圈共享同一个恢复管理器。启动准备或发送遇到冷树时才尝试已核验版本；诊断接口只读，不激活、不刷新焦点。恢复后重新获取同一主窗口的 provider，必要时仅按一次 Tab。
- 发送前保留已有草稿；正文需读回确认后才提交。附件需观察到编辑区域内的真实预览，工具栏图标不能冒充附件。
- 聊天、语音和朋友圈共享桌面锁；暂停、停止或运行代次变化会取消旧任务。成功状态表示本地界面接受，不能当作服务端送达证明。
- 剪贴板使用不可见的所有者窗口；无法完整备份时保留原内容。仅在仍拥有本次写入的内容时恢复；用户中途复制新内容会取消后续覆盖。
- 语音检查播放与录音设备、录音状态和时长，结束或失败后分别尝试恢复播放、录音的三个 Windows 音频角色。清理失败会记录警告，已被界面接受的语音不会被误报为未发送。优先使用按住说话按钮；右 Alt 开关仅允许在按钮不可用时使用后备，未观察到录音状态仍停止。
- 朋友圈兼容已核验的主窗口嵌入结构：文字使用右击菜单，图片使用标准文件名输入框并在打开前再次读回路径；图片缺少可信预览或预览控件被替换时停止。发现已有编辑器或文件对话框时保留用户操作，取消本次自动任务。发表前再次核对正文，包括图片朋友圈的空正文；最终点击不会夺回已改变的前台焦点。最终按钮只在本次编辑器内匹配，要求主窗口仍在、朋友圈列表可读且编辑器关闭；控件树消失或微信退出不能冒充成功。UIA 空树会显示明确诊断并阻止未经确认的发送。
- 可写 ValuePattern 优先；定向写入核验同主进程、编辑器/窗口/发表面板的非空 RuntimeId、前台及空草稿。调用值模式后异常、读回偏移或身份变化均停止，不能再键盘粘贴。无值模式且尚未尝试写入时才使用原焦点核验后备。
- 最终发表调用前设置 `submit_attempted`；调用后失败、取消或窗口状态不确定保留 `outcome_uncertain`。自动流程在提交前保存固定持久意图，结果不确定、重启中断或历史写入失败时停止后续决策、生图和发表，并在面板提供人工核对。

## 恢复范围与后续验收

配置项 `uia_recovery_enabled` 默认开启；关闭后不再激活，并尝试还原项目自己持有的状态。只有版本、SHA、映像大小及进程/模块身份与已复核清单完全匹配时，才能操作固定的单个数据字节。未知版本或未知 SHA 不试写候选地址；原值已是 `1` 时不认领、也不还原其他工具的激活。

当前没有查到腾讯官方提供的固定 UIA 恢复开关，也没有找到针对本机空树、无需修改微信进程或系统设置的可靠恢复方法。讲述人不能当作保证可用的修复办法。

独立 `uia_recovery.py` 的命令行仍只读：分析磁盘 DLL，或核验指定进程后仅读取两个已复核状态字节。[本机探测证据](uia_probe_4.1.13.65.json)记录模块 SHA256 `8f7406a8a465e851ee10eaecccb572d0e5b4e00d480c770938c714c396097b74`、映像大小 `198553600`，以及 `0xAE2B0C8`、`0xB5F7BD8` 最初运行值均为 `0`。前者是唯一允许修改的地址；后者仅供只读核验。离线指令匹配和距离证据本身不构成语义验证。

恢复事务保留原进程句柄，检查启动时间、程序/模块路径、版本、完整 SHA、模块大小、原值和不可执行的可写映像页。每次真实写入均重新核验完整 SHA 和页面；正常关闭、停止或退出时条件还原，身份/页面改变时拒绝盲写并保留失败信息和句柄。日常发送复用快速元数据检查，不逐条重新扫描 198 MB DLL。流程不修改磁盘 DLL、注入代码、扩大页面权限、写注册表或更改全局读屏设置。

重启脚本先核验项目 PID、解释器、创建时间和绝对 `main.py` 命令行，再核验本地面板的实际监听 PID。它通过正常会话与操作凭证请求停止，只有明确确认 `uia_restore_result.ok=true` 才终止本项目进程；无法确认还原时保留进程和 PID 元数据。模拟测试也覆盖中断发生于写入或还原过程时保留恢复句柄、随后重试。

剩余完整消息接收回复链、聊天图片/表情和语音需要分别实机验收，不能由朋友圈或外部文字机制验证代替。诊断必须实际观察到搜索入口、目标聊天标题和可读编辑器；控件恢复不放宽目标、草稿或发送确认条件。

## 依据与适用范围

- [Microsoft：WM_GETOBJECT](https://learn.microsoft.com/en-us/windows/win32/winauto/wm-getobject)说明标准 UIA 获取窗口、点位或焦点元素时已经会请求应用的无障碍对象。
- [Qt 5.15 官方源码](https://github.com/qt/qtbase/blob/5.15/src/plugins/platforms/windows/uiautomation/qwindowsuiaaccessibility.cpp)展示标准 Qt 在收到请求时激活 accessibility 并获取根对象；这不能保证微信定制实现提供相同控件。
- [pywechat 作者的微信 4.1+ 说明](https://github.com/Hello-Mr-Crab/pywechat/blob/main/Weixin4.0.md)记录讲述人办法失效、部分已有无障碍状态的账号仍可见。这是维护者观察，不是腾讯官方的版本或账号保证。
- [wechatauto-replica 作者源码](https://github.com/fanyuantaier/wechatauto-replica/blob/main/wechatauto/uia_driver.py)记录 4.1.13.65 点分隔控件 ID 和运行状态恢复方案。本项目参考机制独立实现精确模块限制、事务还原和共享管理器，没有采用其多候选逐个试写或全局读屏设置。这不是腾讯公开的稳定接口，新版本须重新核验。

以上模拟测试覆盖误目标、重复姓名、焦点变化、取消、草稿与附件、剪贴板竞争、音频恢复、朋友圈确认及项目进程核验。它们不能替代本机完整发送验收。

## 朋友圈互动与临时恢复租期

浏览、点赞、评论和回复使用主窗口 UIA，共享聊天/发表的桌面锁。朋友圈虚拟列表的头像及菜单由当前 UIA 列表边界、窗口 DPI 和命中控件定位，再读取微信号身份卡核验真实微信 ID；不使用聊天弹窗。操作菜单限定 `mmui::TimelineFloatMenu`，已有草稿和焦点变化会停止。回复在输入前和提交前核验完整回复对象，昵称和正文只能作为已绑定真实 ID 的界面定位信息。

连续操作后封面可能已滚出可视区。受控快捷回顶仍绑定原主窗口及列表，随后核验账号原生ID；小动态最多8次移向上中部，短评论正文落点避开作者链接。移动后的状态检查不可跳过，到期、遮挡或打开非回复界面时停止提交。本轮已连续实发两条定向回复，并按唯一原评论ID、作者ID、新原生回执及完整回复引用核验，各新增一次。

当前构建的定向回复框能通过 UIA 读写正文，但 UIA 与 MSAA 均未暴露画面上的“回复某人”提示。程序只在没有可读提示时使用本机 Windows 中文 OCR，截取已绑定的空编辑器范围并要求完整提示准确匹配。UIA 提示与目标冲突时直接停止。原生动态、评论和作者 ID、完整评论列表、主窗口、焦点及控件身份仍须核验；证据仅限本次操作，最多保留 30 秒。无法区分同一作者在同一动态上的多条评论时，虚拟控件后备路径停止。截图与识别文本不写入日志，不发送到远程 API。

Qt 的虚拟列表可能在编辑器范围返回其所属评论区。后备命中仅接受编辑器父链中同一回复视图下的原评论区，核对真实控件 ID、进程、焦点和完整边界；其他行、遮挡控件、普通祖先或界面变化均拒绝。主窗口每次按已绑定句柄重新取得并核验，避免反复枚举所有桌面窗口；失效句柄不会扩大搜索到别的窗口。

临时恢复事务从首次写入开始计时，170 秒后由独立线程条件还原，重复发送不延长同一租期。恢复不依赖可能被 UIA 卡顿占用的桌面锁；还原失败保留句柄和诊断信息，身份或外部状态变化时拒绝盲写。此线程属于 bot 进程，强制终止整个进程或系统原生接口失效时不能保证定时线程继续运行。
