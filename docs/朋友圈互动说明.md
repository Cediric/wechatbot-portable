# 微信bot：朋友圈互动使用说明

朋友圈互动会按计划刷新微信朋友圈，再结合基础人设、动态和评论上下文，由模型决定点赞、评论、回复评论或跳过。每次浏览最多执行一项互动；没有合适的话时可以只看。

## 开始使用

1. 按[安装与启动说明](../README.md)启动项目，登录微信并连接 WeFlow。保持微信主窗口可用。
2. 打开控制面板的「全部设置」→「机器人」，确认自己的真实微信 ID 与基础人设。基础人设也参与朋友圈决策。
3. 在「AI 自主朋友圈」组填写「决策 LLM Base URL」「决策 LLM API Key」「决策 LLM 模型」。朋友圈互动共用这些模型配置；密钥留空保存会保留已有值，勾选清除才会删除。
4. 在「朋友圈互动」组设置时段、间隔、限额、联系人范围和提示词，然后开启「启用自动浏览与互动」，点击「保存设置」（也可按 Ctrl+S）。总开关默认关闭，保存开启后才会自动运行。
5. 回到「会话工作台」，点击「启动桥接」。已运行的桥接会受控应用保存后的配置，旧代次任务会被取消。
6. 查看「朋友圈互动」卡片的主状态、下次浏览时间和最近结果。需要立即执行一个正常周期时，点击「立即浏览一次」。此按钮仍遵守总开关、时段、限额、冷却和待核对状态。

「启用 AI 自主朋友圈」控制发布自己的朋友圈；「启用自动浏览与互动」控制浏览和社交互动。两项开关可以分别设置。自己的朋友圈配图由正式发布流程调用生图 API，互动功能复用决策模型，不增加另一套密钥。

## 面板入口

| 入口 | 可以查看或操作 |
| --- | --- |
| 会话工作台 → 朋友圈互动 | 定时计划、下次浏览、今日点赞／评论／回复计数、最近结果、立即浏览一次、最近互动记录 |
| 同一卡片 → 调整互动规则 | 跳转「全部设置」中的完整朋友圈互动配置 |
| 同一卡片 → 互动待核对 | 查看原动态、操作文字；回复还显示原评论作者、真实微信 ID 和原评论正文，人工记录已完成或未完成 |
| 全部设置 → AI 自主朋友圈／机器人 | 共用模型地址、密钥、模型名、基础人设；自主发布的独立开关 |
| 发送与设备 | 查看微信 UIA、临时恢复状态、联系人名称同步来源与上游能力 |
| 运行日志 | 筛选具体失败原因、导出当前日志；访问凭证会脱敏 |

工作台顶部「暂停任务」会暂停聊天、自动发布与互动，取消未提交任务；「恢复任务」使用新运行代次。「停止」停止桥接任务并尝试还原临时 UIA 状态。互动卡片的开关保持配置值，恢复桥接后按配置重新安排。

## 互动设置

时间窗口与每日额度按北京时间计算。界面提供以下全部设置：

| 设置 | 默认值 | 用途 |
| --- | --- | --- |
| 启用自动浏览与互动 | 关闭 | 开启后随桥接运行，暂停或停止桥接时暂停 |
| 浏览间隔（分钟） | 15 | 1–1440 分钟，可填写小数 |
| 每次最多查看动态数 | 20 | 1–100；自己与其他联系人的动态合计受此上限约束 |
| 每天最多点赞数 | 12 | 0–100；0 关闭点赞 |
| 每天最多评论数 | 4 | 0–50；0 关闭主动评论 |
| 每天最多回复评论数 | 8 | 0–50；0 关闭回复评论 |
| 两次互动至少间隔（分钟） | 10 | 0–1440 分钟，可填写小数；共同约束点赞、评论和回复 |
| 每日开始时间（小时） | 8 | 0–23，开始时刻计入活动窗口 |
| 每日结束时间（小时） | 23 | 0–23，结束后停止新互动；开始晚于结束表示跨午夜，相同表示全天 |
| 允许互动的真实微信 ID | 留空 | 留空表示全部可见联系人；多个真实 `username` 用逗号或换行分隔 |
| 互动决策提示词 | 温和自主决策 | 结合基础人设控制表达与是否互动，模型可以跳过 |

联系人范围填写 WeFlow 身份数据中的真实 `username`，例如 `wxid_xxx`，也支持微信实际使用的其他合法 username。昵称、备注和未对应到真实 username 的微信号别名不能代替身份字段。朋友圈作者与被回复的评论者都会按该范围检查；自己的动态会额外读取，用于发现需要回复的评论。

每天的计数保留已完成操作及结果待核对操作的预占额度，防止不确定结果绕过上限。点赞只执行实时菜单里的「赞」；发现已经点赞就跳过，不会点击「取消赞」。已有自己的评论、已回复的原评论以及已记录完成的动作会参与去重。

## 模型怎样决定

模型收到本轮核验通过的动态、评论、人设及允许使用的公共记忆上下文，自主选择候选动作或跳过。动态与评论里的文字属于待分析内容，不能更改任务或指定另一个发送目标。

回复候选来自自己动态下的评论，或原始身份字段明确表示回复本人的评论。模型可以选择不答。缺少模型密钥、模型调用失败、身份数据冲突或 UIA 目标无法核验时，面板会显示原因；系统不会编造模型决策或补一个固定回复。

缺少独立评论时间的老动态会在首次观察时建立持久基线，后来出现的新原始评论 ID 才作为新评论处理。补充身份能力或重新启动不会把已观察的旧评论变成新到达；带可靠近期时间的评论按其时间判断。

## 真实身份与微信窗口

动态必须对应真实动态 ID 与作者微信 ID；回复必须另外核验原始评论 ID 和评论者微信 ID。昵称、备注用于找到界面控件，身份由原始 ID 与当前资料对应关系核验。改名会使用新身份快照中的名字；同名、同正文、相同界面文字等无法唯一对应的情况会跳过。

卡片出现「评论缺少可核验的微信 ID」时，这些评论暂不能自动回复。符合条件的浏览、点赞和主动评论仍可进行。上游仅提供缓存昵称、生成的评论编号或无身份的正文时，系统会保留能力提示，不猜测发言者。

UIA 在微信主窗口中操作，按当前窗口、控件边界与 DPI 重新定位，适配普通和最大化的主窗口布局；不会为了回复把聊天拆成独立窗口。微信原生身份卡、朋友圈菜单和图片文件选择器仍按实际 UIA 层级核验。窗口、前台、控件 ID、草稿、回复对象或目标位置发生变化时，会停止本次动作，保留已有草稿。

已核验微信构建可使用「恢复已验证版本的 UIA 控件」。该恢复只临时改变已审数据开关，不修改磁盘程序文件；每次事务从首次写入前开始计时，170 秒租期不会因重复检查续期，独立恢复线程可在 UIA 调用或桌面锁卡住时尝试还原。还原未确认时，系统保留恢复句柄并阻止后续发送。

这个 watchdog 与 bot 在同一进程：强杀 bot、主机挂起或底层 API 停滞时，不能承诺在所有故障下硬性 180 秒内恢复。遇到「还原未确认」，保留日志与状态记录，先完成还原检查，再恢复发送。具体已验证构建及实机情况见 [UIA 验收说明](UIA验收说明.md)。

## 结果不确定时

提交前会持久保存固定编号的互动意图。同一状态库的跨进程锁保护执行与核对；同一 bot 中的聊天、朋友圈发布与互动共享桌面锁。

点击发送或点赞后出现异常、取消、界面消失或无法证明结果时，记录会保留为「待核对」，后续互动冻结。重启、暂停后恢复和重新打开面板都不会清掉这条记录，也不会自动重发。

1. 从任意页面顶部的待核对提示回到「会话工作台」。
2. 根据原动态作者、正文、时间和操作文字，在微信中找到该动作。回复还要核对原评论作者与原文；面板所示真实 ID 保留原身份关联，微信界面不一定直接显示内部 `wxid`。
3. 确实已完成，点击「已在微信确认完成」；确实未完成，点击「确认未完成」。阅读二次确认内容后提交。
4. 核对绑定原提交编号；记录变化或仍在处理中会拒绝本次确认，请重新查看。确认只恢复正常周期，不触发立即重发原动作。

记录损坏或原评论关联无法读取时，核对按钮会禁用。保留 `data/moments_interactions.sqlite3` 与日志，不删除数据库来跳过冻结；其中也保存去重、每日额度和旧评论观察基线。

## 常见状态

| 看到的状态 | 下一步 |
| --- | --- |
| 关闭 | 在「朋友圈互动」组保存开启总开关 |
| 已暂停／立即浏览按钮禁用 | 检查桥接是否已启动、是否暂停、是否已有浏览任务、待核对记录或 UIA 还原失败 |
| 活动时段外／已达限额／冷却中 | 等待下一正常周期，或在设置中调整规则 |
| 模型不可用 | 检查共用模型地址、密钥与模型名，查看最近结果和日志 |
| 评论身份缺失或部分缺失 | 保持能力提示；等待上游提供真实评论身份，其他符合条件的互动可继续 |
| 待核对 | 先在微信确认结果，再按原提交记录人工核对 |

代码与合成 UIA 测试验证身份、焦点、草稿、取消、限额和待核对保护。它们不代替真实模型和评论回复的实机验收；具体实测操作以[朋友圈实测记录](朋友圈实测记录.md)为准。
