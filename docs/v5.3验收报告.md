# 微信bot v5.3 验收报告

日期：2026-10-12。主项目基于已交付v5.2单独扩展，原压缩包与v5.2交付保留。此报告区分模拟、真实环境和真实微信结果。

## 改造范围

六语言模型独立配置提示词、思考/预算/强度、上下文/输出/超时；AstrBot正常管线直接看聊天媒体；朋友圈单帖主模型阅读、独立决策、立即执行、再下一帖；参考图库与生图提示词子模型；语音复刻与调节；真实actor/证据/预算记忆；自然节奏剩余等待；9页面19组158设置；包内自动自举与离线依赖。

## 多智能体交叉验证

三个执行智能体分别负责聊天/记忆、朋友圈/媒体/声音、便携环境，主智能体负责配置、模型请求、面板与集成。完成后交换审查范围，独立运行跨模块用例。实际发现并修复：

- 图片/视频取消令牌Event与callable合同不一致导致朋友圈读取失败。
- 缓冲原图在未交付outbox前缺缓存引用保护。
- 群内下一批消息的顶层发言者沿用上一批。
- 超快回复错误继承被跳过请求的旧计时；真正UIA短气泡缺间隔。
- 部分成功发送语音/文字气泡漏记助手日志，旧线程发送结果可能污染记录。
- OpenAI推理模型不接受默认temperature；不支持的思考参数不隐式回退。
- 删除内置参考图前先改配置，失败却有副作用。
- 移动便携目录后的FFmpeg路径不重定位；未知WeFlow整个ASAR未严格拒绝。
- 本机无Key模型被AstrBot SDK拒绝；已有AstrBot用户全局设置被初始化覆盖。
- 热更新provider实例无限保留，改为32代上限并明确提供包内重启入口，不关闭进行中的模型请求。
- 记忆清空确认与真实删除范围不一致、详情原消息ID字段绑定错误，以及抽取范围设置与运行上限不一致。
- 自主朋友圈入口误拒绝本机无Key模型；统一由共享请求模块验证地址与凭证资格。
- 视频抽帧缺少年龄回收；增加保守清理并保护在途消息、outbox及确认后租约，数据库不可读时暂缓回收。
- 上一条朋友圈操作滚动后封面不可见，导致下一条账号核验失败；补在已绑定主窗内受控快捷回顶并核验账号原生ID，取消和移动后状态检查保持有效。
- 小动态位于底部、短评论中心命中作者链接时难以可靠回复；导航最多8次把动态移向上中部，正文落点避开作者链接。遮挡、错界面及操作超时仍在提交前停止。

各修复有独立回归或真实模块mock验证，最终结果见下文。

## 真实环境验证

- 包内uv0.13.0、Python3.12.12、桥接隔离环境、AstrBot4.28.2隔离环境安装与import检查通过。两个依赖锁按SHA校验；159项wheel离线来源/本地纯Python重包记录随包提供。
- 空缓存、离线no-index、require-hashes重装AstrBot依赖通过；FFmpeg/ffprobe9.0.2可实际运行。
- Windows自带PowerShell5.1实际解析4个UTF8 BOM脚本成功；全新无runtime目录、离线模式，从包内归档和轮子完成managed Python、bridge/AstrBot隔离环境、官方init及FFmpeg准备，退出码0。未调用系统Python、winget或Git；此验证仍在当前Windows，不是纯净Win10系统。
- 隔离AstrBot WebUI返回HTTP200，OneBot监听可连接，随包配置插件真实加载。测试进程正常结束，未修改现有微信/WeFlow。
- 实际AstrBot合成带图OneBot消息→本机模拟API→一次模型请求、一次发送调用，实际payload含模型、main prompt、enable_thinking、thinking_budget、max_tokens、image_url及真实ID关联fixture；无需额外caption模型。
- 同一真实管线的群聊3帧媒体也只调用一次主模型、一次群发送；修改模型/提示词/思考/输出上限后下一事件生效，旧在途请求保持旧快照。专属控制台正常退出成功，退出码0。
- 未填写主模型API Key时，实际AstrBot面板仍返回HTTP200且OneBot监听就绪，未调用付费API。
- 真实FFmpeg合成1秒320×180视频，抽4帧并编码给主模型，原文件保留、临时帧清理；两次抽帧+编码约0.922秒，此小样本不代表所有视频延迟。
- 真实Edge浏览器9页158字段；跨页未保存草稿/统一保存、内置参考预览与选择、记忆真实API证据/消息ID/更新时间和清空确认、桌面1440px和移动390px无横向溢出、无页面脚本错误。

## 既有实机证据

v5.2已在本机微信4.1.13.65主窗口完成文字发送、有图/无图朋友圈发布、刷新、点赞、评论、核验原评论ID/评论者ID后的定向回复；不通过独立聊天弹窗代替。临时UIA恢复状态已还原。记录见[UIA说明](UIA验收说明.md)、[朋友圈记录](朋友圈实测记录.md)、[v5.2历史报告](交付验收报告.md)。本轮没有重复发表这些测试动态。

## 本轮朋友圈连续回复实机验证

在微信4.1.13.65最大化主窗口中，项目公开方法连续完成本次测试动态下两条原评论的定向回复。上一条操作将封面滚出可视区后，下一条仍在同一主窗口内回顶并核验账号原生ID，没有使用独立聊天弹窗。小动态向上中部移动最多8次，不能排除遮挡时停止；短评论修正为点击正文，避开作者链接。

两次调用均为`submit_attempted=true`、`outcome_uncertain=false`、`acknowledgement=native_comment_record`，取得唯一新增原生回执并确认`exact_target=true`。独立智能体对提交前、公开动作参数及原生来源逐项核对：原动态一致，原评论ID及作者唯一且此前未回复；新回执ID不存在原始ID或别名碰撞；自己的作者ID、大小写敏感的完整正文、`ref_comment_id`、`ref_author_id`全部对应。

原生评论数量依次为2→3→4，每轮恰好新增一条；第一轮提交后记录与第二轮提交前记录一致。最终两个原目标各有一条自己的定向回复，零错发、重发或结果不确定。本轮用户确认的范围仅为这次测试动态，两条目标现均不再待回复；不据此宣称历史评论已全部处理。本地界面与原生记录接受证明仍不等于服务端送达确认。

早期系统托盘弹出层和Codex通知遮挡时，操作在提交前被拦截，零提交；修正前点击短评论中心误开作者资料卡，也被防误发检查拦截，零提交。回顶加账号核验的两次样本为10.17秒、8.91秒，早期逐步滚动样本为117.55秒，单次快捷回顶探测为1.38秒；这些是本机小样本，不保证其他列表或电脑的延迟。

每轮临时UIA恢复均还原，最终独立只读检查两个状态值均为0。WeFlow从唯一托盘入口正常退出，恢复原HTTP API字段并保留其他设置与托盘关闭行为，再由原程序正常重启；清理核验确认正常运行。公开记录只写方法和结果，真实账号ID、评论原文、截图和完整私有回执保留在包外。
