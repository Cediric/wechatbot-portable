# Windows 微信的界面兼容性

微信bot 通过 Windows UI 自动化（UIA）在微信主窗口找到聊天、输入框和朋友圈控件。只要微信提供所需控件，即使版本未列在下表，也会先走正常流程。微信须在已登录、可交互的桌面上运行。

部分构建会隐藏控件。需要临时恢复时，桥接会核对当前主窗口进程实际加载的 `Weixin.dll` 的版本、完整 SHA-256、架构和映像大小。全部匹配才会临时调整已复核的进程内状态，操作结束后还原。未知构建若缺少必要控件，对应操作会停止。

## 已收录的恢复构建

| 微信版本（AMD64） | 已验证的范围 |
| --- | --- |
| 4.1.13.65 | 实机验证主窗口恢复、聊天发送、朋友圈纯文字与带图发表，以及浏览、点赞、普通评论和定向回评。 |
| 4.1.15.13 | 实机验证恢复后能读取搜索框、聊天标题和编辑器，并能还原原值。验证范围限于控件读取与还原。 |
| 4.1.15.50 | 完成签名、模块和相关函数的离线核对，以及模拟恢复测试。此构建尚无实机发送记录。 |
| 4.1.15.56 | 实机验证恢复与还原、文字、图片和语音发送。配合 WeFlow 6.3.2 还验证了朋友圈带图发表、刷新、点赞、普通评论和定向回评。 |

具体 DLL 哈希和映像大小见[内置构建列表](../wechat-weflow-bridge-ob11/uia_build_profiles.py)。同一版本号也需核验实际文件。

## 升级微信后无法发送

1. 打开控制面板的「发送与设备」，核对实际微信版本、主窗口控件状态和恢复方案匹配结果。
2. 若显示未知构建且必要控件不可读，双击包根目录的 **收集只读诊断.bat**。包内桥接环境就绪后，报告写入 `portable/runtime/只读诊断报告.json`，记录模块版本、哈希、匹配结果和端口监听状态。
3. 若问题发生在启动面板之前，查看 `portable/runtime/startup-error.txt` 中的失败阶段。[便携启动与排查](../portable/README.md)
