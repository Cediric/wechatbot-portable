# 微信bot v6.11 验收记录

修复推送连接失败后仍将重试间隔重置为半秒的问题。失败依次等待 0.5、1、2、4、5 秒，后续保持 5 秒；只有本轮有效的 HTTP 200 连接才重置。停止或代次变化不再连接，已经置位的发送取消事件不会使循环空转。响应发布与停止通过同一生命周期锁协调，连接与读取操作仍在锁外。异常日志只记录错误类型，避免打印带密钥的请求 URL 或服务正文。

修复微信前台判断依赖 Qt UIA 包装值的问题。Windows 环境以实时原生 HWND 和 PID 交叉核验，只接受确切目标或真正的子窗口，不放行同一进程的其它顶层弹窗。只有最小化时恢复窗口，保持最大化布局；必要的线程输入关联反序释放。成功出口重新检查取消、窗口身份与实时前台。原有聊天目标、身份、草稿、发送结果及临时恢复核验保留。

394 项 UIA、朋友圈与相关模拟回归通过；14 项推送重连测试通过，包括日志保密与停止发布竞争；core/lifecycle 129 项必要回归已通过。不同代理交叉复核并复现取消与窗口身份漂移边界，相关问题修正后探针复验通过。本轮测试未向实际微信或朋友圈提交内容。

本机新日志中的消息推送 403 已独立只读确认：WeFlow 的 `messagePushEnabled` 为 false，接口正文为 `Message push is disabled`，连接密钥匹配。其界面开关是左下角头像 → 设置 → API 服务 → 主动推送。关闭开关时不会有真实消息监控；单纯让 HTTP 长连接返回 200 不能证明上游数据库已经完成初始化。

当前 WeFlow 自身另有侧栏不响应及数据库 `-105` 状态错误。用户正在重新安装，配置、密钥存储及必要资料已在包外备份。本机项目按用户要求正常退出，项目进程为零，桥接与 AstrBot 三个端口已释放。本报告不宣称重装后的上游服务或前台操作已经实机恢复。

自用配置保持最近已授权的控制面板快照，未以旧配置、测试数据或机器连接状态覆盖。原人设、模型、音色、参考图与素材保留。交付包不包含运行数据、重新安装备份或原始诊断日志。
