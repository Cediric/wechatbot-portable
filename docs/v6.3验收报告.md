# 微信bot v6.3 验收报告

本轮按照用户要求仅修改本地源码、配置及桌面两份完整便携包，未操作服务器、微信或模型 API。

## 改动

- 移除单条大约字数、流式目标字数和整次回复最多字数三个聊天面板控件；实际 schema 为十九组一百八十七项，配置模板和字段文档由 schema 同步生成。
- 主模型提示词设为通常每条微信消息不超过十五字，以完整自然短句表达；明确需要详细说明时可以适当超过。不通过硬截文字限制长度。
- 自用配置及共享角色卡取消旧的整轮二十五字规则；运行时也忽略旧配置遗留的字数预算，沿用旧配置不会重新触发长度拦截。保留角色关系、主人真实身份绑定、禁字母与标点约束。API、模型、推理设置、上下文、克隆音色和三张参考图保留。
- 普通回复按完整句及换行分泡，超出气泡数量后合并完整尾部；流式只在完整句及换行处出泡，取消无标点长文的字符阈值分泡，保留既有最大缓冲保护。
- 主聊天、群聊判断、拟真与朋友圈决策、发布决策和生图提示词读取同一份共享角色卡及身份规则，再添加各自任务要求。记忆抽取及摘要读取事实证据，不扮演角色；实际生图和语音分别接规划后的画面提示、最终台词及音色。
- 同次 UIA 操作复用已观察的控件树，导航、主窗口变更和无障碍恢复后重新扫描，编辑器、标题、焦点、草稿和 HWND/PID 仍在发送前现场核验。只有当前标题区能证明原生 ID 与目标对应才省去重复搜索；没有此证据仍按原搜索流程。
- 添加脱敏阶段计时，按本轮票据摘要关联桥接和 AstrBot；记录缓冲、决策、准备、首段正文、首个完整句及本机首条发送确认。取消、失败和重复序号不冒充当前轮首条成功。不修改用户所选模型、思考设置或上下文。
- 按用户要求恢复初版右 Alt 录音方式：默认启用且优先使用原扩展按键手势；支持已静态核验的微信四点一五录音状态文案及同进程专用弹层，保留录音证据、听写排除、取消、目标和设备还原。没有真实录音状态仍不虚报成功。
- 自然照片请求进入独立生图流程，成功后直接发送原目标；生成失败和发送未确认不谎称已发，不自动重发。收到图片附件本身不会默认为生图请求，明确按附图创作仍可进入流程，附件仍交主模型理解。
- 固定协作约定由代码注入全部六种语言模型，私聊的专用提示覆盖也保留；摘要有单独固定职责。主模型收到可信枚举组成的本轮输出计划和图片执行结果，不注入辅助模型的自由推理或理由。可编辑提示及原角色卡继续保留，不能借原提示标记省掉固定流程注入。

## 验证范围

本地六百零二项最终定向回归通过，覆盖自然分泡、共享人设、输出字符规则、流式传递、部署后插件加载、相关上下文、面板、朋友圈决策及发布、UIA 控件恢复与版本适配、计时边界、照片请求、语音路径和固定工作流注入。合成浏览器预览通过十九组一百八十七项控件、九页桌面与三百九十像素移动端、跨页草稿、保存和参考图/记忆交互，三个旧字数控件在实际页面和 schema 均已移除，主模型提示词显示十五字要求，未出现浏览器脚本错误。

两句合成 UIA 发送基准中，普通无可见原生 ID 窗口的全树扫描由二十六次降为六次，仍执行两次正常搜索；当前会话有核验 ID 时，扫描降为四次、搜索降为一次。此数据只证明模拟控件扫描次数减少，不能换算成服务器提速秒数。

交付版本已统一为六点三，桥接状态、OneBot 版本接口、插件注册与元数据、诊断、文档及包名同步；同步后另跑四十三项插件、工作流和面板冒烟检查及三十项协议检查通过。后续交付主动递增版本的约定保存在根目录 AGENTS.md，同轮构建重试不重复递增。

用户补充的旧运行日志中，两例从接收消息至发送器确认分别约四十八秒和五十一秒；推送至 AstrBot 后分别约四十六秒和四十九秒。旧日志没有模型首段或 UIA 开始时标，因此只能定位等待主要在推送之后，不能判定模型与发送各占多少。该日志另有录音状态未确认、连续输入取消旧轮和聊天编辑器核验失败；本轮未宣称这些实机问题均已解决，也未宣称达到某个实际回复秒数。

独立代理比较六点一自用配置，角色卡、主模型提示词、三个被移除的长度字段及用户明确要求恢复的右 Alt 开关改变，其余模型 API、选择、音色、预算与素材配置保留；辅助人设及普通长句/完整尾部核验通过。两份完整包由构建器逐项校验清单、内容哈希、压缩包完整性与公共/私人差集，并另由独立代理核验；最终 ZIP 的 SHA 在桌面随包文件中，详尽机器可读结果保留在本地工作目录。

本轮没有重新进行纯净 Windows 10 整机测试或服务器实机发送；六点一已有的环境、只读文件、进程归属与主窗口 UIA 修复继续包含在完整包内。若模型不给句末标点，流式会等待该段生成完再发，以保留完整句意。
