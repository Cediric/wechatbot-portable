# 微信bot v6.21 验收报告

日期：2026-10-23。本版针对六点二十进行本地代码复查，优化已确认的重复等待和异常处理。没有替换用户人设、模型、密钥、声音参数或朋友圈计划。

## 修复与优化

正常重启时，AstrBot 环境可复用先前完整导入成功记录；相同包位置、依赖锁和检查程序下，只定位 SDK 入口并执行原生 AES 测试。首次启动、环境重建或变化，以及“检测修复环境”仍执行完整导入。快速检查失败会回到完整检查，完整检查未成功不保留旧成功记录。此项减少启动阶段重复初始化，不表示聊天模型网络耗时缩短。

语音缓存的共享等待者原先调用无期限等待，取消后仍可能占用回复流程。现在等待期间定期观察取消，唯一的合成请求继续供未取消者复用；不增加第二次付费请求。新语音的过期文件清理由每次遍历目录改为在目录与保留期未变时每十分钟最多一次。已确认发出的语音若记忆落库失败，仅记录该持久化错误，同轮已准备图片仍继续发送，避免把已发语音误判失败。

群聊原生艾特标记原先只加速入队，未贯穿缓冲与媒体解析。现在判断上下文和判断失败回退都保留它，联系人或机器人显示名变化后仍能识别直接叫到机器人的消息。正常判断为不回复仍然有效；真实会话和发言人编号继续负责路由。

朋友圈单条坏媒体保留自身冷却，取消它对全局评论检查的额外一分钟延迟。对阅读输入未改变的动态复用主模型已有阅读结果，最多缓存六十四条、五分钟，评论、媒体及模型配置变化会失效；决策与需要输出的文案仍按本轮生成。回评轮询先读取原生内容并决策，选中实际动作后才刷新界面，每条操作仍按阅读、决策、执行顺序完成并让位私聊。WeFlow 提供的仍是本机缓存，新评论发现速度取决于它的同步，本次不宣称改善未同步内容的发现时延。

运行监控采样与启动、停止、配置重连按同一生命周期锁协调；锁忙时跳过本轮判定并维持心跳。恢复判断移入启动锁，避免刚进入恢复时旧启动路径重建发送取消标记。外部状态恢复不在该锁内等待。

## 验证范围

分支针对性验证完成后，合并执行聊天、群聊、流式、语音缓存、生命周期、朋友圈、便携启动与长路径相关五百五十八项回归，全部通过，耗时三十一点二七秒；这是测试套件耗时，不是实际回复速度。独立代理另行交叉运行朋友圈六项、运行及语音七项、启动快查五项边界验证。

本轮采用合成消息、模拟模型和桌面接口进行相关回归，使用真实标准库子进程验证便携检查脚本与运行监督边界。没有启动真实微信、WeFlow、桥接服务或付费模型，没有服务器实测；不能据此承诺历史 UIA、语音前导静音或网络生图错误在服务器已消失。启动快查不逐文件检查手工修改过的第三方依赖；需要完整检查时可运行“检测修复环境”。

多代理分工复查后互相复核缓存、生命周期及朋友圈调度。完整双包审计核对版本、文件清单、源码一致性及相对六点二十的修改范围；自用配置、角色资料和参考图逐字节保留，运行缓存和会话数据不进入交付包。最终结果记录于包外 final-v6.21-independent-zip-audit.json。
