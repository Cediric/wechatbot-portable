# 微信bot v6.0 验收报告

日期：2026-10-12。本版以独立候选目录完成改造；保留原项目及上一版运行目录。干净包与自用包使用相同公共源码，自用内容按明确清单增加。

## 交付行为

- 主模型直接理解聊天、群聊和朋友圈媒体，采用真实流式请求；完整短句按序发送，同一轮所有气泡共享字符预算。推理内容不发送到微信。新输入取消旧请求，过时图片和语音不会发送。
- 六个语言模型角色独立配置接口、模型、提示词、思考设置、上下文及输出预算。主模型上下文最高五十万；自用选择二十五万六千。接近主模型预算时摘要同会话完整旧轮次，记忆抽取保留原始证据片段。
- 拟真与朋友圈互动共用独立模型，按真实微信身份读取相关聊天和互动记录。群判断复用已有请求，不额外调用一遍拟真模型。生图提示词子模型接收相关记录、角色状态和实际决策，公开配图不能泄漏私聊或伪造线下经历。
- 发布决策每150分钟、主动点赞与评论每240分钟，新评论每5秒检查。私聊在途或结束后不足60秒时让出朋友圈；无待回复评论时不刷新微信界面。首次观察建立历史基线。
- 自用回复整轮最多25字，口语，禁止字母及标点白名单以外的符号。限制覆盖聊天、朋友圈及语音台词；内部身份、阅读摘要、决策格式和生图提示词保留必要信息。
- 千问图像模型保持所选型号，支持三张参考图；关闭内置提示词优化，使用独立提示词子模型。克隆语音核验服务端模型绑定，原速、原调、音量50，轻松闲聊偶尔使用并遵守冷却与轮次。
- 控制面板9页、19组190项设置，月白青绿布局，项目名为微信bot；跨页草稿统一保存，敏感凭据不返回明文，支持桌面与手机宽度。

## 多智能体交叉验证

执行者完成各自模块后由其他智能体独立复验。最终交叉审覆盖流式输出、角色禁律、媒体策略、拟真上下文、朋友圈优先级、生图取消、语音配置快照与克隆绑定、便携入口及依赖完整性。审查中实际发现并修复：

- 图片先于正文禁律核验发送，以及无可信票据的分包绕过整轮25字上限。
- 外部语音自报合法台词绕过正文守卫、SDK异常正文未正确结束当前流式请求。
- 历史语音头片段残留状态使已完成私聊长期阻塞朋友圈。
- 聊天与发布调用遗漏生图子模型的相关上下文和取消信号。
- 模型指定语音绕过自动开关和冷却，短口语角色的自动语音门槛不可调整。
- 版本含点号的克隆音色被错误拒绝、热更新期间核验和合成串用不同配置、删除后的旧查询重新授权缓存。
- SDK成功语音返回使用WAV长度占位符。仅对已确认成功、固定规范头的有效PCM封装实际长度，保留对其他无效或截断声音的拒绝。
- AstrBot重启入口在缺少第三方模块的基础Python中导入生命周期模块。改为通过参数委派桥接环境执行正常退出，保留进程归属核验；超时不强杀。
- Windows PowerShell从其他终端继承模块路径时找不到自带Get-FileHash。启动入口只在本次进程前置自身标准模块目录并保留继承路径，不修改系统环境。
- 用户反馈的深目录启动失败：已在Windows PowerShell 5.1复现。Python目标根目录172字符时，部分归档成员超过260字符，Expand-Archive失败后的回滚再报缺少_asyncio.pyd，掩盖了长路径原始原因。改用原生Windows扩展路径API，预检归档名称和目标、核验固定SHA及逐文件内容、原子写入、成功后标记；不删除已有目标目录。关键文件缺失或变化会修复，标准库导入失败会全量复查。[PowerShell同类问题](https://github.com/PowerShell/PowerShell/issues/27671)
- 插件源码目录与实际AstrBot安装目录的层级不同，正文守卫错误地按父目录定位桥接模块。改为使用已核验的包根目录，并按实际源码路径隔离模块缓存；新增真实复制安装目录回归，保留原生身份票据及整轮字数守卫。
- 深目录安装虽完成，实际SDK依赖的一个262字符文件仍被普通Python导入器报告找不到。确认原文件完整后，为本包两套独立环境安装私有模块和pth入口，仅将已有且属于本包解释器的搜索路径转换为Windows扩展路径；外部目录、相对项、顺序、系统设置和官方CLI不变。环境烟测增加实际AstrBot API及依赖导入，避免安装成功冒充运行就绪。

## 实机与交付边界

目标机器随后反馈环境和AstrBot初始化均通过，但完整启动在WeFlow核验阶段报ASAR数据块校验失败。只读检查实际已核验的原始及修改后WeFlow 6.3.2程序包：两者完整SHA均匹配，54847个内置文件中有5个空文件，每个合法记录一个空内容SHA；旧校验器错误计算为空列表。因此按[Electron官方规则](https://raw.githubusercontent.com/electron/asar/main/src/integrity.ts)统一空文件块摘要处理，非空整块不增加空尾块，保留全部固定完整性检查。实际原始包497272852字节，只读重建后497307416字节，整个输出SHA仍精确匹配之前核验的目标；没有写入运行中的WeFlow或改变配置。新回归覆盖空内容、整块边界、摘要篡改及重包入口。该失败点位于WeFlow备份、配置改写与退出之前。

两名代理分别用完整真实归档独立验证上述修复，其中一份验收还调用原包与修改包的实际适配预检查，在首个备份创建前停止；进程关闭、配置写入及网络调用均未执行。PowerShell入口的4项真实5.1子进程回归证明：固定阶段在慢子进程退出前显示；同样内容的错误流、附加私有内容及任意原始输出不会即时显示；失败保留阶段与脱敏后的异常，路径捕获入口仍只读取标准输出。

后续收到远端自用包目录带“(1)”的AstrBot环境准备退出1反馈。原入口将捕获的子进程异常丢弃，外层报告只能看到泛化退出码。另建全新115字符包根、175字符物理Python根、含括号的隔离目录，用此前冻结源码强制离线检查，59.673秒退出0；这次检查仍没有覆盖联网时的依赖选择。

用户提供目标机器的独立排查结论：联网安装选择了aiocqhttp源码包，uv缓存临时构建路径出现WinError 206；使用内置已校验轮子及禁止构建后安装成功。随后35秒导入上限又被冷启动超出，实际astrbot.api约40.5秒、anthropic约14.5秒，热导入约20秒。该机器在仅调整runtime后，原入口prepare和check均返回0；这是用户提供的目标机证据，不能写成本机亲自实测。已将禁止源码构建、本地轮子安装、180秒AstrBot导入上限及真实错误记录落实到启动源码，供全新包使用。

本地真实SDK另复现了宿主ASTRBOT_ROOT指向普通文件时导入检查退出1；新的检查采用本包专用沙箱，去除初始化/重置口令变量，避免影响宿主目录和正式实例。还修复官方初始化中途留下.astrbot标记后被误认为完成、首次口令未保存的续跑缺口。上述额外修复不作为远端这次失败的根因。

最新源码另经独立普通启动模式冷安装验收：包根115字符，包含中文、空格、方括号和括号，物理Python根175字符；没有设置WECHATBOT_OFFLINE或UV_OFFLINE，uv缓存为空，外部索引故意设为不可达本地地址。150个发行包全部从包内锁定轮子安装，实际命令包含禁止构建、禁止索引和哈希核验；没有临时构建目录、没有依赖重装。总49.535秒，其中创建环境0.689秒、安装33.657秒、真实AstrBot API及anthropic导入14.747秒。宿主ASTRBOT_ROOT指向的合成哨兵未改变，导入检查没有创建正式实例或包根data；没有启动服务、操作微信或调用模型API。这覆盖此前遗漏的普通联网启动依赖选择路径，不能当成纯净Windows 10整机启动实测或速度承诺。

115字符带括号目录的最终复用检查，在子进程注入无效宿主ASTRBOT_ROOT和初始化/官方重置口令变量，24.602秒退出0。外部哨兵内容和修改时间、正式登录文件、面板口令哈希、两份配置字节均保留，父进程环境未改变。真实SDK官方CLI另在隔离实例验证：已有.astrbot但缺配置时恢复成功；持有真实FileLock让首轮初始化返回1后，诊断保留Cannot acquire lock file，释放锁重试成功并复用先前保存的口令。两场恢复均用实际SDK口令算法核验同一合成密码，完整配置、平台、供应商和插件定位齐全；再次准备不改密码或配置。该验证没有替换CLI参数、启动服务或调用API。

本版没有再次操作微信发送。主窗口UIA、最大化窗口、有图及无图朋友圈、点赞评论和定向回复的实机证据来自上一版，见[v5.3验收报告](v5.3验收报告.md)、[朋友圈实测记录](朋友圈实测记录.md)与[UIA验收说明](UIA验收说明.md)。上一版两条定向回复的UIA耗时58.03及55.38秒，平均56.71秒，仅表示那两次界面操作，不代表新模型读取与决策总耗时。
