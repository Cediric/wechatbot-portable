# 微信bot v6.22 验收报告

日期：2026-11-01。本版将蓝色大肥鱼项目中适合现有微信架构的记忆保存、发送反馈和媒体追问机制接入现有运行链路。继续使用 AstrBot、WeFlow 接收和微信主窗口 UIA 发送，不执行外部项目安装器，不替换人设或服务配置。

## 本版行为

群聊参与判断之前就保存收到的原始记录，按真实会话和发言人归属；不接话不等于丢弃证据。明确的“记住”请求将原话作为证据保存，不等待模型。记忆抽取任务写入现有 SQLite 数据库，内存队列只负责调度，队列满和重启不会丢掉已接收任务。失败任务冷却后继续，旧证据迟到时不能覆盖更新的同类事实。

处理 `/reset` 或 `/new` 前，先将该会话未处理的原始证据提交到持久化记忆队列，再转交确切命令。此处只做本地数据库操作，不同步等待记忆模型。同批命令前后的消息分开处理，群命令使用实际发出命令的成员身份。清空同时移除该会话短期媒体关联和发送反馈，不删除已经保存的长期事实。

文字、语音、图片和表情的实际发送结果进入短期反馈，下一轮主模型和辅助决策能区分生成稿与已确认发送。语音已发不表示同句文字也发过；图片已生成不表示已送入微信。分段文字只发出一部分时，仅把已发部分记入历史；取消不能覆盖此前已确认的发送。此机制不增加模型请求、不重发不确定内容，也不替换现有桌面发送器。

同一真实会话中的同一人先发图片、视频或表情，再发相关追问时，可以重新带入已取得的本地原始媒体，由主模型直接理解。明确追问最多关联三分钟内的媒体，短句隐含追问窗口为四十五秒；缓存有数量、文件总量与过期上限。不同发言人、不同群和私聊之间不共用这条关联。图片及视频帧租约持续到本轮交接完成，避免清理时提前删掉仍需要的文件。

银月角色卡保留“注意，改编了，银月现在不是韩立的剑灵，是烟尘倦客的。”。主模型仍负责所有对外内容，决策模型只选动作；现有模型、凭据、声音参数和参考素材保持当前自用基线。运行机器的账号、连接令牌和自动探测路径仍由目标机器初始化。

## 验证

合并执行本轮变更相关的聊天、记忆生命周期、媒体关联、发送反馈、输出分流、流式、复制插件及上下文压缩回归，共三百四十九项全部通过，耗时十二点八九七秒。这是离线测试耗时，不是实际微信回复速度。结果记录于包外 `final-v6.22-regression.log`。

三个子代理分工实现并交叉复核记忆、媒体关联和发送反馈，主代理集成主聊天插件及清空命令。交叉审查发现并修正了分段回退部分成功漏记、异步语音待完成状态被误当成功、图片发送成功后取消覆盖回执等边界问题。

双包独立审计核对版本、逐文件清单、公共源码一致性及相对六点二十一的改动范围，核对自用配置、角色卡和八项参考资源。包外记录为 `final-v6.22-independent-zip-audit.json`。

## 范围与限制

本轮验证使用合成消息、模拟模型及桌面接口，不调用付费模型，不启动真实微信、WeFlow 或服务器服务。未做服务器实机验收，因此不据此宣称历史 UIA、语音前导静音、朋友圈定位或网络生图问题已经消失，也没有真实回复耗时下降的测量结果。

发送反馈是进程内的两小时短期状态，不跨重启保存，也不证明对方已读；近期媒体关联同样是短期缓存。长期记忆使用现有事实检索体系，没有引入新的向量数据库。尚未提交抽取的原始用户证据可超过普通五百条历史保留数，以便清空时完整交接；关闭记忆时不会执行这套保存和抽取。两种交付包均不带开发机聊天或记忆数据库。
