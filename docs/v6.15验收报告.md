# 微信bot v6.15 验收报告

日期：2026-10-17。针对用户最新服务器日志 wechat-bot-log-2026-10-17 (1).txt，并只读对照最初 Wechat-bot-v5.1.zip。完整干净包与自用包统一为 v6.15。

## 日志确认的回归

模型及桥接处理多为约一至三点五秒，目标定位却每条需要约七至十秒，文字提交另约五至六秒。后续代码要求标题直接显示真实微信编号才能复用会话，而实际标题显示昵称，因而同人连续气泡反复搜索。最初版保存最近联系人跳过搜索；本版恢复有效复用，同时保存原生身份与实时控件证明，避免只按昵称认目标。

昵称在接收桥接中存在，但主模型的身份说明只写原生编号，丢失称呼资料。现按同一真实编号绑定当前昵称、备注及群名；这些值作为结构化显示数据而非指令，不凭昵称认主，也不将群成员的私聊备注导入群聊。

最新日志语音合成成功，约一点七至二点七秒。失败发生在录音手势前的编辑器、草稿或焦点核验。原版右侧Alt键录音实现仍保留；修复编辑器内部叶子焦点、设备切换后重新获取实时编辑器，并精确清理本请求被取消的未提交文字。用户原有草稿、已按发送键的内容不被清理。

## 朋友圈与出口

最新日志没有再次出现媒体HTTP400，但仍有主窗口/列表无法确认、滚动命中无法对应、真实同名同正文评论歧义，不能将媒体读取改善等同于朋友圈恢复。

微信主窗口定位支持原生句柄对应的虚拟子节点和冷启动控件树；朋友圈列表支持已知时间线类、Pane角色及布局包装。完成滚动后重新取得同物理窗口中的实时控件，保留账号、原动态、原评论和提交前窗口核验。导航探针跳过动态与评论深树。诊断记录具体子阶段及窗口和控件属性，不记录昵称、正文、推理、凭据或签名地址。

两次评论写作只有隐藏推理，没有最终正文；结束原因为stop，完成用量分别约二十八和六十六token，并未耗尽用户配置的四千零九十六输出预算。本次将仅有一个文本出口的评论写作改为主模型直接输出正文；兼容旧text字段，但不使用决策草稿、不发送其他出口字段、不用推理冒充正文。用户模型、思考强度和预算保持不变，没有自动付费重试。

新私聊抢占而明确未提交的朋友圈操作持久记录为取消，不再显示执行失败。真实评论编号仍有歧义时不猜第一项；仅在驱动明确尚未提交时继续其他独立动态，该目标遵循已有失败冷却。提交结果不确定时仍保留待核对记录并停止。
