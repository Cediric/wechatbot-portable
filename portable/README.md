# 微信bot v6.32 便携运行说明

适用于 Windows 10 / 11 **64 位**。解压整个文件夹到可写目录，先打开并登录微信和 WeFlow，再双击根目录 **一键启动.bat**。不要直接在压缩包里运行。

微信和 WeFlow 须选中同一个机器人账号。一键启动会核对 WeFlow 的所选账号目录和联系人真实微信 ID。如果旧配置填入了带四位后缀的目录名，核对成功后会自动纠正。朋友圈互动支持从原版 WeFlow 的联系人接口读取身份映射，再用微信资料卡的微信号确认账号。[v6.28 验收报告](../docs/v6.28验收报告.md)

已核验的 WeFlow 6.3.2 HTTP 服务会拒绝空令牌，虽然其界面提示留空无需验证。请在其 API 服务设置中生成连接令牌。启动器兼容 WeFlow 本机加密存储的令牌，使用当前 Windows 用户验证解密后同步到本包连接配置，保留 WeFlow 原存储。更换 Windows 用户或复制其它机器的加密配置后无法读取时会明确提示，不能把密文直接填入机器人密钥框。WeFlow 数据库组件的 `-105` 状态错误属于上游尚未就绪，需先在 WeFlow 的连接测试中恢复数据库，不能通过清空令牌解决。

聊天接收还需要 WeFlow 的“主动推送”开关：左下角头像 → 设置 → API 服务 → 主动推送。该开关关闭时 `/api/v1/push/messages` 返回 403；重连会退避等待，避免半秒重复刷日志。开启后的消息监控仍需要 WeFlow 数据库连接成功，HTTP 通道可连接与真实消息已开始监控分别核验。

## 第一次启动

启动器使用 Windows 自带 PowerShell 5.1，自动准备本文件夹内的 uv、Python 3.12.12、两个互相隔离的 Python 环境、AstrBot 4.28.2 与 FFmpeg/ffprobe，然后启动桥接和 AstrBot 并打开两个控制面板。无需预先安装 Python、Git、winget，也不修改全局 Python 或 PATH。

工作台的 **停止机器人** 会停下收发、朋友圈、记忆抽取及本包 AstrBot。面板保持打开，可随时点 **启动机器人**。需要移动、更换或删除便携包时，选 **完全退出**。看到退出成功后即可操作文件夹，下次双击 **一键启动.bat** 重新打开。

运行依赖已经内置，安装及修复使用包内锁定轮子，禁止从源码包临时构建；普通联网启动也采用这条路径，避免深目录构建越过Windows路径上限。缺少轮子时明确报错并要求补齐完整包；文件不符合固定 SHA-256 时会停止。若系统缺少微软 x64 Visual C++ 运行库，启动器会从微软下载、核验 SHA-256 与数字签名，再通过标准 Windows UAC 安装。请允许官方安装程序；取消 UAC 后修复并再次启动即可。

Python 与 uv 归档使用经过校验的原生 Windows 长路径解压，支持中文、空格和较深的目录；不需要修改系统长路径设置。之前启动中断留下的不完整运行文件会按归档修复，已有配置、记忆和密码保留。解压全部成功后才写完成标记，复用时再次核验关键解释器与库文件；不会因为只剩一个 python.exe 就认为环境完整。启动错误详情保存在 `portable/runtime/startup-error.txt`。

包内两套独立Python环境还会安装私有长路径兼容模块，使实际依赖导入能读取深目录下的文件。它只转换当前包解释器已有的本地搜索路径，不改变系统注册表、全局环境、其他Python安装或自定义sitecustomize；官方AstrBot启动入口与进程核验保留。首次安装、依赖锁或包位置变化，以及“检测修复环境”会实际导入AstrBot API及相关依赖。完整检查成功后，普通重启复用该记录，只定位SDK入口并测试原生AES，减少重复初始化的等待；快速检查失败时回到完整检查及原有修复流程。实际服务启动仍需通过原有就绪检查。

环境准备失败时，控制台和 `portable/runtime/startup-error.txt` 会记录创建环境、安装依赖、实际导入或首次初始化等具体阶段，并保留脱敏后的原始异常。外层退出码不会覆盖本次Python诊断；报告隐藏凭据、配置对象、命令参数及异常源码行。排查时可提供这份错误文字，无需分享配置或登录密码。日志中的退出码本身不能判断是联网、磁盘还是导入问题。

服务启动阶段会分别报告桥接或AstrBot的退出码、等待上限、日志位置及本轮脱敏错误；只摘取本次创建服务后写入的日志，无法核验日志来源时只提供位置。便携启动等待服务最多180秒，外层等待220秒；提前就绪立即打开，超时继续保留尚在运行的服务。删除旧日志不妨碍下一轮重新诊断。

就绪检查同时验证本包进程记录、实际监听进程和实例目录。Windows虚拟环境的启动器与实际Python子进程可以不同，只有核验映像、创建时间、命令及父子关系后才接受；其他包或其他程序占用端口不会被报告为本包已启动。日志摘录还核验启动时的末尾内容和文件身份，截断重写后不能混入旧日志。

一键启动还在同一百八十秒等待期限内，读取已核验桥接的连接状态：桥接正在运行并已完成 OneBot 握手，才报告完整启动成功并打开面板。冷启动期间连接尚未建立会继续等待；超时明确提示 OneBot 连接检查，不把面板端口开放当作聊天链路就绪。单独打开面板和单独启动桥接仍可用于配置排查。

命令行核验优先使用包内psutil原生读取，避免每次检查都启动PowerShell/CIM；查询后再次核对进程创建身份。外部解释器缺少原生读取库时仍可使用CIM，超时保留具体查询和秒数，命令参数继续隐藏。

便携一键启动会在启动两个服务前，检查配置的桥接面板、AstrBot 面板和 OneBot 端口。实际监听进程可核验为旧微信bot时，先使用当前代码正常停止旧桥接并还原 UIA，再请求旧 AstrBot 正常退出，等原进程释放端口后启动新包。合法管理解释器及官方模块子进程也可核验。旧桥接的 bridge.pid 缺失、损坏或陈旧时，直接依据实际监听进程的创建身份、解释器及绝对 main.py 入口核验，不补写旧记录；停止后仅清理确实属于该进程且字节未变的记录。此流程不执行旧包代码、不迁移或覆盖旧配置、记忆及 AstrBot 数据；如需延续旧历史，仍须备份并迁移对应数据。无法核验的监听或旧 AstrBot 记录会显示端口和进程编号，陌生程序不自动退出。服务尚未创建时仍标明“预期日志位置”，该文件可能不存在。

双击 **收集只读诊断.bat** 可生成 `portable/runtime/只读诊断报告.json`。它读取实际主窗口对应进程所加载模块的文件版本、哈希及映像大小，并列出本包支持与匹配的恢复构建；同时检查本机监听状态和诊断文件是否存在。报告不包含用户目录、账号、聊天、原始日志、配置、密钥或密码；不读取构建状态字节、不操作界面或启动服务。需先准备包内桥接环境。

AstrBot首次导入检查最多等待180秒，并在包内专用沙箱执行，避免宿主的AstrBot目录设置影响检查或提前生成正式实例密码。导入超时会记录真实阶段并退出，不重装已经完整的依赖。首次初始化中断时复用已保存的口令重试官方初始化；已有配置和密码不会重置。

控制面板的主模型、其他模型和 API 密钥均由你配置。主模型未配置时仍可打开面板，聊天回复暂停；启动不会自动调用付费 API。AstrBot 的首个登录密码保存在本包 `portable/runtime/astrbot-instance/dashboard-login.txt`，用户名为 `astrbot`。登录后建议修改密码。

先安装并登录微信和 WeFlow。一键启动会为匹配已核验构建的 **WeFlow 6.3.2** 备份并安装扩展。若 WeFlow 的关窗行为设置为退出，启动器最多等待 35 秒，进程退出即继续。若设置为收至托盘且出现退出提示，请右键 WeFlow 托盘图标选 **退出**，再双击 **一键启动.bat**。

WeFlow程序包中的合法空文件仍有一个空内容数据块摘要，校验按Electron官方规则处理，同时保留完整文件、所有数据块和整个程序包的固定哈希检查。校验失败发生在备份、配置改写及退出WeFlow之前，会停止本次适配。启动器实时显示固定准备阶段，便于区分正在安装、导入或核验WeFlow；其他原始输出继续先脱敏。

## 根目录入口

| 脚本 | 用途 |
|---|---|
| 一键启动.bat | 检测、修复并启动桥接、AstrBot和控制面板 |
| 打开面板.bat / open_panels.bat | 打开当前配置的两个面板 |
| 检测修复环境.bat | 准备、修复本包环境；不启动或修改微信和WeFlow，不安装系统运行库 |
| 收集只读诊断.bat | 生成脱敏的模块构建、监听状态及诊断文件元数据报告 |
| 重启桥接.bat | 通过本项目的进程身份验证重启桥接 |
| 重启AstrBot.bat | 核验本包记录的PID、创建时间、程序、命令行和AstrBot实例；向本包独立隐藏控制台发送Ctrl+C，正常退出后再启动 |
| 安装语音驱动.bat | 从VB-Audio官网下载校验驱动并打开官方安装器；允许UAC后点击Install Driver，完成后重启电脑 |
| 离线启动.bat | 仅使用已内置的环境依赖启动；系统运行库/语音驱动首次安装及在线模型仍可能需要联网 |

重启入口不会按端口结束其他服务，也不会强杀无法核验的进程。已有其他程序占用面板端口时，请先更改本包端口或确认占用程序。

## 主模型与多模态

私聊和群聊的聊天调用仍由 AstrBot 执行。本包插件将控制面板中的主模型地址、密钥、模型、提示词、思考选项、上下文预算、输出长度、温度和超时应用到这个平台；其他平台的自定义配置保留。

每条消息固定一份配置快照。控制面板保存参数后，下一条消息使用新配置，正在运行的请求继续使用原配置。图片、表情帧和视频抽帧直接送进同一次主模型请求；不增加图片描述模型调用。媒体旁保留原微信会话ID、发言者ID与消息ID关联。为保护正在运行的请求，最多保留32个主模型配置版本；达到上限后面板会显示重启提示，请双击 **重启AstrBot.bat** 释放旧版本。

## 文件位置与迁移

- 桥接配置、模型参数：`wechat-weflow-bridge-ob11/config.json`。
- 记忆等用户数据：桥接的数据目录；保留现有目录即可。
- AstrBot实例、会话、密码、插件和数据库：`portable/runtime/astrbot-instance/`。
- 运行器、环境、缓存和检查报告：`portable/runtime/`。
- 固定依赖、原始运行归档和许可证：`portable/vendor/`。

移动自己正在使用的整包前，先退出本包桥接和AstrBot，再移动文件夹。启动器会重新建立包含旧绝对路径的本包Python环境，并迁移已明确属于本包的附件与FFmpeg路径；用户自定义外部路径保留。现有配置、角色卡、会话和记忆不会重置。分享给别人应使用干净交付包，勿直接分享自己使用后的 `config.json`、数据库、`runtime` 或密码文件。

## 语音与联网限制

未检测到虚拟声卡时，文字、图片、视频帧和面板仍可启动。本包保留语音启用的默认值，首次一键启动发现声卡缺失时，会自动下载并核验官方驱动安装器，请允许UAC并点击Install Driver；取消或失败会继续启动其他功能。关闭语音时只检查并提示，独立入口“安装语音驱动.bat”随时可用。安装器退出不代表你已经点击安装；完成安装后按官方说明重启，再检查设备。运行报告会记录此次驱动安装请求与待重启状态。检测修复环境、prepare/check和打开面板不会安装驱动。

微信语音录制/播放还需要正确选择 VB-Cable 设备，并设置声线/克隆声音的API参数。启动器不能替代Windows的授权、官方安装按钮与重启。

本包内置运行环境并不包含微信、WeFlow安装程序和API服务。在线主模型、决策、生图、语音等接口需要网络及有效配置。微软运行库和VB-Cable安装器由各自官网按需下载，不在交付包中再分发。纯净Windows 10虚拟机未在本次环境中执行；此前已完成当前Windows上的隔离环境安装、无缓存离线依赖安装、真实AstrBot/OneBot/本地模拟模型、多帧群聊和正常退出验证。

## 来源、锁定与许可证

`runtime-manifest.json` 记录运行归档来源与固定SHA-256；两个 `requirements-*.lock` 使用带哈希的独立依赖锁；`vendor/vendor-manifest.json` 列出159个Windows/Python3.12依赖轮子以及所有归档和许可证的大小、SHA-256。仅有PyPI源代码包的aiocqhttp/jieba已从校验过的原包构建为纯Python轮子，来源记录在 `vendor/built-wheels-provenance.json`。

另行收录的依赖许可证采用较短的目录，避免解压便携包时再次遇到深目录限制。原轮子及运行归档不变；`vendor/licenses/wheels/index.json` 保留每份许可证的原归档成员路径、当前位置、大小与SHA，依赖清单同时指向对应文件。

Python归档来自Astral维护的python-build-standalone，原文件逐字节重打包为ZIP，由包内原生长路径解压器展开；未改动解释器或库。FFmpeg二进制来自ffmpeg.org列出的Gyan Windows构建，原归档、GPL许可证和README均保留。所有依赖许可证仍在各原轮子/归档内，并另收录于 `vendor/licenses/`。请保留这些文件及对应软件的许可证义务。
